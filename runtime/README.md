# runtime/

The GOAL2 driver (G1): DOSBox-X in WSL, headless, driven by keystrokes; screens read from text-mode video memory; savestates, and memory read from them (apt's DOSBox-X 2024.03.01 has no debugger: G1's spike reads the screen and memory from savestates). It drives the released original as a black box.

- `spike/`: T02's spike (F001), kept unchanged; its probes wrote measurements, not run records.
- `driver/`: the reusable driver (T07, F003). `driver.py` is the library (`Driver.launch(start_state)`, `keys(...)`, `screen()`, `memory(addr, n)`, `save_state()`, `restore(state)`, `terminate()`; `StartState`, `make_state`) and a CLI (`make-state title`, `read <file.sav>`); `savestate.py` parses a DOSBox-X 2024.03.01 savestate (text page and guest memory, offsets from F001; `Savestate.program()` finds GOAL.EXE's MCB, PSP and data segment, and `ds_word(off)` reads a word at `DS:off`, T08); `cycle.py` runs restore → key → screen read → reset and writes one `run/1` record per cycle to `runs/E002/`.

Start states live in `.cache/states/driver/` (git-ignored) with the folder drive C: was mounted from and the drive layout the driver mounted (`drive_layout`, e.g. `mount c <game>`, `mount d <work>/dosclock`); `Driver.restore()`, which every restore passes through, refuses before copying the state or sending Host+L (and `launch()`, `cycle.py` and E003's `run.py` refuse earlier, before any record), a state whose layout is not the driver's or that has none (every state made before T08 rework round 4: restoring one under a driver that mounts D: stalled DOSBox-X), with a `StateLayoutMismatch` naming the state and the command that remakes it (`python3 runtime/driver/driver.py make-state title`; for E003's `main`, `run.py make-main`), after the old `.sav` and `.json` are moved out of the folder; every session mounts `scratch/driver/game`, recreated from the verified release copy. Each wait is a bounded poll or a logged key hold, and each record carries the host UTC and local time of every read. The guest clock starts from the host's unless the config sets `dos_date` (MM/DD/YYYY) and `dos_time` (HH:MM:SS), which the autoexec sets with DOSBox-X's `date` and `time` before GOAL runs (I3, T08); every launch, clock option or not, writes DOS's own `date /t` and `time /t` to a drive D: in the session folder before GOAL runs (so savestates have the same drives either way), `Driver.clock_applied` holds that read-back, and a launch whose set clock DOS did not apply raises `ClockNotApplied`; a restored savestate brings its own BIOS tick count, hence its own DOS time (F004). `terminate()` SIGTERMs the two process groups the driver started and SIGKILLs any group still alive `TERM_GRACE` (0.5 s) later — DOSBox-X ignores SIGTERM after a restore (F003) — logging each process's end method and time, which the record's log carries. `bash setup/goal2-runtime.sh` first; then `python3 runtime/driver/cycle.py --runs 10 --start-state title`.
