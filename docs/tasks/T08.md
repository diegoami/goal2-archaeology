- **Evidence** (pasted):
  - `docs/backlog.md` Q001: *Fresh launches whose DOS time differs in the hour or minute reach different
    main screens, and launches whose DOS time agrees to the minute reach the same one; a quick result
    from one savestate differs between batches only when some named input differs.*
  - Leads from the listing (T06, reviewed, not findings): `214B:0688` is a 16-bit LCG
    (`seed = seed * 0x7ABD + 0x1B0F`, returns 1..n), reached through `214B:06B1`, `214B:06D0`,
    `214B:06FA` with the far pointer at `DS:A978`, which `214B:206A` sets to `DS:7B62`.
    `23E4:11D7` (INT 21h AH=2Ch) stores CX (hour, minute) at `DS:7B62`, DX at `DS:7B64`; its caller
    chain is `1771:6730` ← `1771:76B1` (only when the byte at `[A923]+0x3C` is 2 or 5, the codes
    `1771:580B` names "qualifying") ← `0000:0000` once, and `000E:70B9` ← `000E:7439`. A second
    stream: `0791:94C9` uses the seed `DS:8336`, which `0791:F3F2` sets from the BIOS tick count
    (linear 0x46C). `214B:1DA7` is a delay calibration; `214B:0D90` reads the tick while waiting for
    a key. Both seeds are in guest memory, so a savestate holds them.
  - F001 D0/D3: fresh launches with the same keys differ between batches; from one savestate, the
    quick result (`r`) is identical within a batch and differs between batches about 20 min apart.
  - The G1 driver (T07, F003): `runtime/driver/`; records carry host UTC and local time and memory
    reads from savestates. Setting the DOS time or a seed is I3 (`vocabulary/interventions.md`).
