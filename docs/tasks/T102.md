# T102 Possession, ball actions and scoring anatomy (engine study)

- **Kind**: static research; planning brief under [programme #433](https://github.com/diegoami/goal2-archaeology/issues/433).
- **Issue**: [#441](https://github.com/diegoami/goal2-archaeology/issues/441); **Branch**: `task/T102-engine-study`; **Merge after**: T99, T100, T101.
- **Difficulty**: hard; **Size**: M (2–4 active hours, compute separate); **Complexity**: high; **Impact**: high.
- **Rating rationale**: Branching action selection and shared state produce most visible outcomes and require careful cross-module tracing.
- **Implementer**: main session or the session's selected implementer, using repository tools. **Reviewer**: independent strong-model review for new rule claims; milestone review in T113.
- **Evidence**: ball.py, contests.py, duels.py, restarts.py, F022 and F026 plus original named/listing sources.
- **Owns**: `docs/engine-study/ball-play.md`, `notes/engine-study/T102/` (source census and supporting evidence). The executable slice fixes exact source/annotation ownership before dispatch.
- **Scope**: Trace holder choices, receiver selection, passes, launches/crosses, shots, interceptions, headers, tackles, keeper duels, goals and disallowed/own-goal paths. Link selection and contest rules to state transitions and resulting commentary/statistics; keep set-piece management in T104.
- **Acceptance outcomes**: An annotated possession sequence connects inputs, selection, draw, state mutation and visible event. Account for each ball/duel routine family and label differences among normal play, restarts and unvisited branches.
- **Dispatch gate / Done when**: this brief records scope and expected research results, not executable readiness. Split into independently mergeable, approximately one-hour slices before dispatch; each gets its own issue, ownership and contract. Validate each slice's Done-when commands as failing on pre-task main and passing on a mock fix. Require source/evidence checks, relevant controls and `python3 tools/check_links.py`; ordinary research outcomes above remain mandatory.
- **Hazards**: Commentary or statistics can be delayed or omit state changes. A 'shot' branch and a recorded shot need an explicit write/event link.

Use the [programme's methods, rating definitions and gates](../engine-study-plan.md).
New measurements have immutable source-pinned receipts; a budget is set before a heavy job.
This package does not select a production backend or silently repair original behaviour.
