  - `GOAL.HLP` 211–227 (the keys and the main screen): Enter accepts, Esc backtracks, cursor keys
    move the selection bar, the spacebar moves to the next category; F1 help, F3 replay a saved goal,
    F4 load a match summary, F5 print the screen, F7 save the game, F10 quit. Lines 648–657:
    "compatibility and displays". Line 127: a "quick result option".

    `Xvfb` and `xvfb-run` present. Python 3.12.
  - Text mode: the screen of a text-mode DOS program is at segment `B800`, two bytes per cell
    (character, attribute), 80×25 unless the game sets another mode, which this task checks.
  - Intervention levels (game-archaeologist `vocabulary/interventions.md`): reading video memory or
    a savestate is I1; setting memory or the RNG is I3.
  - `run/1` is game-archaeologist's `formats/run-1.schema.json` at `formats-v1` (3365343): one raw,

- **Owns**: `runtime/spike/**`, `setup/**`, `findings/F001-*`, `runs/E001/**`, `capabilities.json`,

- **Scope**: on this machine, record each outcome with exact versions:
  - **Launch, unattended**: DOSBox-X headless (an SDL dummy driver, or under `Xvfb`), mounting a copy
    of the release's files from `.cache/` (git-ignored), never the owner's folder. Which
    configuration (machine type, cycles, memory) the game needs.
  - **Observe**: read the text screen from video memory, through DOSBox-X's debugger or another
    route you find, and compare it with a screenshot once. Record the video mode.
  - **Act**: one keystroke takes effect, shown by a before/after screen read.
  - **Reset**: terminate, and restore a known start state, by a DOSBox-X savestate, a fresh launch,
    or both.
  - **What the game writes**: the file set before and after a session that saves (F7), listed in the
    finding as the proposed `runtime_writes`.
  - **Determinism**: from one start state, does the same key sequence give the same screens? Try at
    least two sequences that pass through a random event, if one is reachable from the main screen
    (a quick result, or a played match), and say what varies.
  - **Speed**: how fast the game can run (cycles, the turbo setting) without breaking input or
    screens.
  - `setup/goal2-runtime.sh`: installs nothing, checks the tools and versions, unpacks the release
    into `.cache/`, and ends with a one-line `ready` or a list of what is missing.
  - **Not in scope**: a reusable driver, any game rule, unpacking or decompiling `GOAL.EXE` (G3),
    the record tools (G2).

- **Hazards**:
  - losing measurements: every probe output goes under `runtime/spike/measurements/` or `runs/E001/`,
    committed and pushed after each batch, never deleted or overwritten (game-archaeologist L207);
  - committing an original file, a savestate or a DOSBox-X capture of the game's files;
  - treating "it ran once" as unattended launch;
  - fixed sleeps without recording them: every wait is either a poll for a screen or a recorded
    delay;
  - mounting the owner's folder (`/mnt/c/...`) instead of the `.cache/` copy;
  - interpreting a screen as a rule ("the match is random"): record what was read; the
    interpretation goes in the finding, cited.
