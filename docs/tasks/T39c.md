# T39c Screens read back from a sitting's video (a test)

- **Kind**: spike, with a go/no-go answer (no game run)
- **Issue**: #139 · **Branch**: `task/T39c-video-screens` · **Merge after**: T39a (its renderer)
- **Implementer**: the owner's choice at dispatch · **Reviewer**: the owner's choice at review
- **Why**: every key is logged, but a screen is kept only when a savestate is written, and fast
  scrolling loses most of them (#128: 313 of 537 requests in E015-r0007). The recorder also films the
  game window. If a frame reads back to the exact 80x25 text, every key gets its screen before and
  after, whatever the saves do — possibly instead of #128's recorder change.
- **Protects**: the answer's honesty: "go" only if frames decode exactly where a savestate gives the
  truth; any misread character is counted, never smoothed over.
- **Evidence** (pasted):
  - Sitting 20261011-161003: `video.mkv`, 322,866 bytes, 639.1 s, window geometry 1280x800 at
    (1005, 561) (`meta.json`); 224 snapshots with their text screens and staging times in
    `index.jsonl` (request window `request_s`..`sent_s`, T34); all 397 presses in `keys.jsonl`.
    Its folder is on both of the owner's computers, not in git (rule 18).
  - T39a's renderer gives the exact pixels of a text screen from its chars, attributes and font.
- **Owns**: `experiments/E022-video-screens/**`, `tools/screens/video.py`, `tests/test_screens_video.py`.
- **Scope**:
  1. Decode the video's frames (ffmpeg, named with its version) and find the text grid: cell size,
     offset, scale.
  2. For each of the 224 snapshots, take the frame at its request window and decode it to 80x25
     characters and attributes by matching each cell against the font's glyphs (T39a), exact match or
     nearest with its distance; compare with the snapshot's own screen.
  3. Report: cells decoded exactly / all cells; screens decoded exactly / all; the worst cases with
     their PNGs; whether the frame rate catches each key's screen (the time between consecutive
     presses against the frame times).
  4. `notes.md`: go (every screen exact, or misreads only in cells a rule identifies and excludes,
     stated) or no-go, with the numbers.
- **Done when**:
  1. `python3 experiments/E022-video-screens/check.py <session>` prints `screens exact: N/224` and
     `cells exact: M/(224·2000)` and exits 0; the numbers are in `notes.md` with the verdict.
  2. A test pins the decoder on 3 committed frame crops (PNG, under the experiment) with literal
     expected text.
  3. `python3 -m unittest discover -s tests` and `python3 tools/check_links.py` pass.
- **Hazards**:
  - the frame for a snapshot is chosen by the snapshot's request window, never by searching for the
    best-matching frame (that would hide timing errors);
  - frames are GOAL2 material: crops in this private repository only, no video committed;
  - push after each step; a draft PR after the first push.
- **Runs on**: a machine holding the sitting's folder · cloud: C0 · network: N1 (GitHub)
