# T04 Static inventory: unpack GOAL.EXE, map its code, propose GOAL.DAT's structure (G3)

- **Kind**: research (static)
- **Issue**: #5 · **Branch**: `task/T04-static-inventory` · **Merge after**: T01
- **Implementer**: the main session or a scoped helper using caller-configured model/settings; no fixed model or automatic per-task spawning. See [model policy](../model-policy.md).
- **Reviewer**: independent under the repository review rules; caller-configured model/settings, without a named-model requirement.
- **Why**: the match is a moving simulation (`docs/plan.md`), so the rebuild depends on reading the
  engine. Before any static research question can be asked, the executable must be unpacked,
  disassembled reproducibly, and mapped by area; and `GOAL.DAT`'s layout must be proposed.
- **Evidence** (pasted):
  - `GOAL.EXE`: 92,391 bytes, sha256 in `artifacts/known.json`; `file` reports "MS-DOS executable,
    MZ for MS-DOS, LZEXE v0.91 compressed". LZEXE 0.91's format is public: a small decompressor stub
    and a bit-stream of literal bytes and back-references, followed by a packed relocation table.
  - `GOAL.DAT` 44,040 bytes; `ALTER.EXE` 25,622 bytes (probably the data editor); `Y.HIL` 3,989 bytes,
    unknown. The help file promises 128 countries, a pool of 100 players per country and a squad of
    20, 12 skills and the other player attributes (`GOAL.HLP` 22–49).
  - U16 allows unpacking and decompiling; U17 allows derived extracts in this private repository
    (`static/`), never the original files. A finding's basis for a static claim is
    `static:listing`, `static:decompile` or `static:bytes`, naming the binary's sha256 and an
    address or offset (game-archaeologist `vocabulary/basis.md`).
  - The tools available without `sudo`: Python 3.12, `pip` into a virtual environment inside the
    worktree (e.g. `capstone` for 16-bit x86 disassembly). Ghidra and other installs are the
    owner's step: name what would be needed, and why, in the finding.
- **Owns**: `tools/static/**`, `tests/static/**`, `static/**`, `findings/F002-*`
- **Scope**:
  - **Unpack**: `tools/static/unlzexe.py`, a decompressor for LZEXE 0.91 written from the public
    format, producing a plain MZ executable. Record the unpacked file's sha256 and size.
  - **Disassemble**: a reproducible listing of the unpacked code (16-bit real mode, relocations
    applied as segment references) into `static/goal-exe/`, with the tool and version named, and a
    script that regenerates it byte-for-byte.
  - **Map**: an index of the code by area of `knowledge-map.md`, as far as strings, calls and data
    references show it: which routines touch the help-file's areas (the match engine, player
    attributes, competitions, the save and data files). Each entry is an address range with its
    evidence; anything inferred is marked as inferred.
  - **`GOAL.DAT`**: its structure proposed from its bytes (record sizes, string tables, counts that
    match the help file's 128 countries, the pools, the 12 skills), as representation claims
    `R001…` in the finding, each with its byte evidence. No claim is decoded beyond its evidence.
  - `findings/F002-static-inventory.md`, from game-archaeologist's template, status `proposed`.
  - **Not in scope**: running the game (G1), any rule of the game, `ALTER.EXE` and `Y.HIL` beyond
    naming what they are, editing `spec/` or the knowledge map.
- **Done when**:
  1. `python3 -m unittest discover -s tests/static -v` exits 0, including a test that unpacks a small
     LZEXE fixture the tests generate or embed (not the original), and a test that fails if the
     relocation table is ignored.
  2. `python3 tools/static/unlzexe.py <the released GOAL.EXE> scratch/goal.exe` exits 0, and the
     finding records the output's sha256 and size; running it twice gives the same sha256.
  3. The listing script regenerates `static/goal-exe/` with `git diff --exit-code static/` clean.
  4. Every representation claim in the finding cites `GOAL.DAT` byte offsets, and the reviewer checks
     two of them against the released file.
  5. `git ls-files | grep -iE '\.(exe|dat|hlp|hil|pif|bat)$'` prints nothing (the unpacked
     executable stays in `scratch/` or `.cache/`), and no tracked file is larger than 1 MB.
  6. The finding's `## What this does not establish` names every area the map could not place, and
     every inferred entry.
- **Hazards**:
  - committing the unpacked executable: it is the original's code, so it stays out of the tree like
    the original;
  - a listing that cannot be regenerated, or depends on an unnamed tool version;
  - naming a routine by guess ("the match engine") without the strings or calls that show it;
  - decoding `GOAL.DAT` fields beyond what the bytes show.
