# T06 The research backlog: falsifiable questions per area, each with its routes (G5)

- **Kind**: architecture (research planning)
- **Issue**: #15 · **Branch**: `task/T06-research-backlog` · **Merge after**: T02, T04, T05
- **Implementer**: the main session or a scoped helper using caller-configured model/settings; no fixed model or automatic per-task spawning. See [model policy](../model-policy.md).
- **Reviewer**: independent under the repository review rules; caller-configured model/settings, without a named-model requirement.
- **Why**: G-M3 needs every area the rebuild uses to be `supported`, each by static and behavioural
  findings. That work needs an ordered list of questions, each saying how it would be answered.
- **Evidence** (pasted):
  - `knowledge-map.md` and `sources/goal-hlp.md` (T05): 17 areas `documented`; each has candidate
    questions the help file implies.
  - F001 (T02): the runtime, its speed, and an uncontrolled input that changes between batches.
  - F002 and `static/goal-exe-map.md` (T04): `GOAL.EXE` unpacked, Pascal-style, its routines indexed
    by area. Not placed: skills and attributes, ageing, fitness, country strength, rankings, the
    other managers, the match engine's simulation. `GOAL.DAT` holds no player skills (R013).
  - Handover #13: Q001–Q004 come first (the uncontrolled input, `cycles` and the half timings, the
    quick result's engine, where skills come from).
  - The owner's decision (2026-10-04): full questions for the G-M3 areas (match engine, attributes,
    ageing, fitness and morale, team analysis, positions and formation, tactics, discipline,
    competitions, the other managers, countries' strength, the squad); one-line placeholders for
    friendlies, sacking, several human players, data files and `ALTER.EXE`.
- **Owns**: `docs/backlog.md`, `docs/plan.md` (one link to the backlog in the G5 row)
- **Scope**: `docs/backlog.md`, a table of questions `Q001…`, ordered by what G-M3 needs. Each row
  has: area, the question, the falsifiable prediction (with its `GOAL.HLP` line, where there is one),
  the behavioural route (what to run under the G1 driver, and n), the static route (routines or
  `DS:` addresses from the map or F002, or "not placed": where to search), what it unblocks, and the
  difficulty for routing. No status column: status lives in issues.
- **Done when**:
  1. `python3 tools/check_links.py` passes.
  2. `wc -w docs/backlog.md` is under 12,000.
  3. `awk -F'|' '/^\| Q[0-9]/ && ($6 ~ /^ *$/ || $7 ~ /^ *$/)' docs/backlog.md` prints nothing (no
     empty route cell).
  4. Q001–Q004 are the first four rows and are the four questions of handover #13.
  5. Each G-M3 area named under Evidence has at least two rows: `grep -c` per area name is pasted.
  6. Every routine address in the backlog is a routine in `static/goal-exe/routines.tsv` (a command
     that checks it is pasted, with its output).
- **Hazards**: a question that cannot fail; a static route that names an address the map does not
  hold; deciding a design question in the backlog (research never decides design).
