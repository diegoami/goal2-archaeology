- **Scope** (as delivered): One further entry of the comparison harness, `Route(image, entry="play_action")`, harness-only.
  One `call()` is **one press** of the manager menu's Play action, run by `main_menu_loop` 000E:7439's own code from
  000E:772A (the target of 7722 `cmp ax, 6; je 772A`) to 000E:77CB, where every path of the branch ends. Neither 57E5
  nor 77BF is the entry: 77BF is the branch's last step and 57E5 its second. The record carries the original's own
  decisions as `("action", ...)`; looping presses until a round is played is the caller's (`Route.round()` does it).
  1. **The site is established from the disassembly and cited**, with the stack and BP chain, in route.py's docstring.
  2. **The original's order, not ours.** The harness hooks and calls no pre-step routine; a control fails if it does.
  3. **The existing entries are unchanged.** `route_fixture` and `play_round` keep their sites, stacks, purity, records,
     news capture, key policy and return contracts; `play_round()`/`resume_round()` are not touched.
  4. **Refusals stay strict.** An unknown entry still raises; a non-registered build is refused for the new entry as
     for the others. (`Route` has no started/completed/foreign Machine to refuse: those live in `Match` and
     `resume_round`.)
  5. **No new options.** No seeds, delays, managed/tail/engine or port-body changes, no player policy, no table
     edits, no active saves, no new port.
