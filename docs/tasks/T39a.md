# T39a The screen catalogue and the screenshot renderer

- **Kind**: tool + data (read-only over the committed records; no game run)
- **Issue**: #137 · **Branch**: `task/T39a-screen-catalogue` · **Merge after**: —
- **Implementer**: the owner's choice at dispatch · **Reviewer**: the owner's choice at review
- **Why**: a driver or bot that does not know a screen's keys gets stuck (T28's stall), and the
  owner can answer "what do I press here" fastest from a picture (the owner, 2026-10-11). T39 is
  split by layer (process.md §2): T39a catalogue + renderer, T39b the coaching kit, T39c the video.
- **Protects**: the catalogue's truth: every key row names its source, and nothing in it is
  invented — a row comes from a screen's own text, a recorded key and its before/after screens, the
  code, or the owner.
- **Evidence** (pasted):
  - Screens print most of their keys: "Use ←→↑↓ keys to browse, then hit ◄┘ to select", "use INS to
    swap between world and continental rankings", "F2-new name R,C-reposition T-tactics ◄┘-take off
    this player Esc-exit", "Hit Y for yes, N for no", "F1help F3load goal F4load summary F5print
    screen F7save F10quit", "spacebar-pause ←→-speed", "hit any key", "Esc,◄┘-bench" (E015-r0007,
    states 3, 76, 28, 16, 27, 14, 207; `E015-r0007-mined.md` on PR #134).
  - Every E015 record stores each state's text screen (80x25, chars and attributes, and its CP437
    text) and, for real sittings, the key map: bursts of presses with the screen before and after
    (`keymap.py`; T34's rules: a burst is mapped only when bracketed, never a per-key causal claim).
  - Real sittings: E015-r0003 (2026-10-07), E015-r0007 (2026-10-11); r0004–r0006 are scripted
    acceptance sittings; r0008 a 22 s false start.
  - Pillow is not installed; the standard library writes PNG (zlib, struct).
- **Owns**: `tools/screens/**`, `static/screens/**` (the catalogue), `tests/test_screens*.py`,
  `docs/screens.md`.
- **Scope**:
  1. **Renderer**: `tools/screens/render.py <record> <state>` (or a savestate) → a PNG of the 80x25
     text screen as the game shows it: the 16 VGA attribute colours, blink as bright background off,
     the glyphs of the font the savestate itself holds (VGA plane 2 in the Vga component, if found;
     else a named, pinned CP437 8x16 font, saying which). Standard library only.
  2. **Screen identity**: a screen kind is named from its fixed text (title words, frame), not its
     digest (a digest changes with every name and number); `tools/screens/identify.py` gives a
     state's kind or `unknown`, with its rule per kind in the catalogue.
  3. **The catalogue** `static/screens/catalogue.tsv`: per screen kind, per key: the key, what it
     does or where it leads, and the source — `screen` (its own hint line, quoted), `run:<run id>
     state <n>` (a mapped burst: before → after), `static:<path>:<line>` (left empty here; later
     tasks fill it), or `owner`. Built by `tools/screens/build.py` from the committed records; hand
     rows only with source `owner`.
  4. `docs/screens.md`: how to read and extend it; an unknown screen goes to the owner as a PNG.
  Not in scope: driving the game (T40), the recorder (T39b), the video (T39c), code reading of the
  key handlers.
- **Done when**:
  1. `python3 tools/screens/build.py` rebuilds `static/screens/catalogue.tsv` byte-identical to the
     committed file from the committed E015 records; every row has a source; every `screen` row's
     quoted hint text occurs in that record state's text; every `run:` row's before and after kinds
     are the ones `identify.py` gives those states.
  2. `identify.py` names every state of E015-r0003 and E015-r0007 or says `unknown`, and the PR lists
     the unknown count per record; no kind's rule matches states of two different kinds the PR shows
     side by side (the test pins 3 pairs of different screens).
  3. `render.py` renders E015-r0007 states 16 and 76 to PNG; the test decodes the PNG it wrote
     (standard library) and checks size 640x400 (or the font's cell × 80x25, stated), and that the
     pixel colours at 3 named cells equal the attribute colours of those cells; the PR attaches
     both PNGs.
  4. `python3 -m unittest discover -s tests` passes; `python3 tools/check_links.py` passes.
- **Hazards**:
  - a key row with no source, or a `run:` row read from one burst as a per-key cause (T34: a burst
    is "screen before, presses, screen after");
  - screen kinds keyed by digest (they would split one screen into hundreds) or by one common word
    (they would merge different screens);
  - GOAL2 material stays private: PNGs and screens go to this repository and the owner only;
  - no game run, no Ghidra; push after each step; a draft PR after the first push.
- **Runs on**: any machine · cloud: C0 · network: N1 (GitHub)
