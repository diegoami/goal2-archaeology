- **Owns**: the new checkpoints and their manifests under the experiment this repository keeps taker inputs
  in; `docs/` where roles 2 and 5 are described, extended to 3 and 4; the tests that read them.
- **Scope**: Collect targeted **unchanged-original-key** checkpoints for the penalty (role 3) and free-kick
  (role 4) taker decisions, to the standard roles 2 and 5 already meet. The task protects one claim: **a
  consumer can recognise and answer a role-3 and a role-4 taker decision from kept evidence, not from a
  guess.**
  1. **Role 3 first**, by the path above: it is reproducible today and it is what blocks goal2#695.
  2. **Each checkpoint carries what #400 asks**: an input immediately before the actual decision, the
     role/side/highlight/current-pick frames, and the Space → board → CF3A extra blocking read.
  3. **Role 4** the same way. If no deterministic path to a free kick is found within the task's bounds, say
     so and deliver role 3 alone rather than synthesising one — a partial, honest delivery unblocks goal2#695,
     which only needs role 3 to pass round 7.
  4. **Unchanged original keys only.** No guest-memory edit, no forced role byte, no rewound CPU. A
     checkpoint that was reached by anything other than the original's own keys does not establish the case
     (#400 is explicit, and the shootout precedent is named there).
  5. **No catalogue change here.** goal2's `screens.py` entries are a separate goal2 slice that consumes this
     evidence; this task delivers the evidence and its description.
