# T09 Use game-archaeologist's pinned validator and register_artifact.py (ADR-009)

- **Kind**: infrastructure
- **Issue**: #22 (also closes #25) · **Branch**: `task/T09-pinned-tools` · **Merge after**: T08
- **Implementer**: the main session or a scoped helper using caller-configured model/settings; no fixed model or automatic per-task spawning. See [model policy](../model-policy.md).
- **Reviewer**: independent under the repository review rules; caller-configured model/settings, without a named-model requirement.
- **Why**: game-archaeologist now ships the record validator (T07, 4d7b855) and the artifact tool
  (T09, 69566be) for game repositories to fetch at a pinned commit (ADR-009); this repository still
  imports a test script and keeps its own copy of `register_artifact.py`.
- **Evidence** (pasted, from #22 and #25):
  - Use the validator per game-archaeologist `formats/README.md`, "The validator": list it in
    `archaeology.json`'s `uses`; fetch `tools/validate_records.py` with `formats/*.schema.json` at the
    pinned commit, keeping the `tools/` and `formats/` layout; never copy or edit it.
  - `tools/register_artifact.py` (game-archaeologist): subcommands `manifest`, `check`, `validate`,
    fetched beside the validator. Calls change from `register_artifact.py <dir> …` to
    `register_artifact.py manifest <dir> …`; `--writes` still works; `--when` defaults to today;
    `known.json` is read from `--known` (default `artifacts/known.json`).
  - Behaviour differences: files matching `runtime_writes` leave `files` (U21); absolute paths, `..`,
    backslashes and drive letters are errors; a special file or unsafe symlink in a checked folder
    fails `check` and `manifest` (U24). The validator rejects NaN/Infinity, duplicate keys (U23) and
    lone surrogates.
  - Today: `archaeology.json` pins `formats-v1` (3365343); `tools/ga.py` imports
    `tests/formats/check_examples.py` and exposes `validate`, `semantic_errors`,
    `canonical_set_hash`, `unknown_keywords`; `tools/register_artifact.py` and
    `tests/test_register_artifact.py` are this repository's copies.
- **Owns**: `archaeology.json`, `tools/ga.py`, `tools/register_artifact.py`,
  `tests/test_register_artifact.py`, `tests/test_validate_runs.py`, `tools/validate_runs.py`,
  `.github/workflows/*.yml` (only if the fetch needs it), `docs/` lines that name the old tools
- **Scope**: protects that every committed record and artifact manifest is validated by the shared,
  pinned tools and nothing else. Bump the pin to 69566be or later; `tools/ga.py` uses the pinned
  `tools/validate_records.py` (its four public names keep their signatures); replace the local
  `register_artifact.py` and its test with the pinned tool (a thin wrapper or a documented
  invocation; never a copy). Not in scope: registering the successor set (#14), changing any record
  or `known.json`.
- **Done when**:
  1. `archaeology.json` pins a commit at or after 69566be and lists the validator and the artifact
     tool in `uses`; no file under `tools/` is a copy of either (`diff` against the fetched files
     prints differences or the file does not exist).
  2. `grep -rn check_examples tools tests` prints nothing.
  3. `python3 tools/validate_runs.py runs/E001 runs/E002 runs/E003` passes with the pinned
     validator; any record that now fails is listed in the PR, not changed.
  4. The pinned `register_artifact.py validate` on `artifacts/known.json` is run and its output
     pasted; any set that fails is reported, not changed.
  5. `python3 -m unittest discover -s tests` and `discover -s tests/static` pass, and CI is green.
- **Hazards**: editing a fetched file; changing a record or `known.json` to make it validate;
  breaking `tools/validate_runs.py`'s callers (T07's and T08's instructions use it).
