# T108 Audit arithmetic, boundaries and record indexing (engine study)

- **Kind**: defect investigation; planning brief under [programme #433](https://github.com/diegoami/goal2-archaeology/issues/433).
- **Issue**: [#447](https://github.com/diegoami/goal2-archaeology/issues/447); **Branch**: `task/T108-engine-study`; **Merge after**: T96, T97, T98, T99; ES-R1 accepted.
- **Difficulty**: hard; **Size**: M (2–4 active hours, compute separate); **Complexity**: high; **Impact**: high.
- **Rating rationale**: Machine arithmetic and edge paths are subtle; wrong results can affect normal play and fidelity.
- **Implementer**: main session, `gpt-6.1-sol` at `high`; perform the task directly.
- **Targeted help**: sparingly spawn a `gpt-6.1-sol` / `xhigh` agent only for the hardest bounded subproblem; no automatic task delegation.
- **Reviewer**: independent Claude or Kimi at the existing checkpoint; never an author of the deliverables.
- **Review checkpoint**: [ES-R2](../engine-study-reviews.md#es-r2); exact entry, scope and exit criteria apply.
- **Evidence**: Attribute/contest analysis, original named/listing sources, port arithmetic helpers, #375 and #412.
- **Owns**: `docs/engine-study/audit-arithmetic.md`, `notes/engine-study/T108/` (source census and supporting evidence). The executable slice fixes exact source/annotation ownership before dispatch.
- **Scope**: Investigate prioritised signedness, overflow, division, off-by-one, sentinel, range, indexing and threshold anomalies. Start from concrete discrepancies or counterintuitive branches; reuse existing reports and minimise each candidate before assigning a defect.
- **Acceptance outcomes**: Every examined candidate has source references, a minimal input, expected/actual behaviour and a disposition: original quirk, port defect, documentation/test defect, unsupported suspicion or unresolved. File confirmed issues with reproduction and acceptance; report explored negatives and unvisited risks.
- **Dispatch gate / Done when**: this brief records scope and expected research results, not executable readiness. Split into independently mergeable, approximately one-hour slices before dispatch; each gets its own issue, ownership and contract. Validate each slice's Done-when commands as failing on pre-task main and passing on a mock fix. Require source/evidence checks, relevant controls and `python3 tools/check_links.py`; ordinary research outcomes above remain mandatory.
- **Hazards**: Nonmonotonic behaviour can be faithful original behaviour. Fixes, golden changes and broad tooling hardening are separate tasks, and a surviving mutant can indicate an observation blind spot.

Apply the [main-session model policy](../engine-study-models.md) and [programme methods/gates](../engine-study-plan.md); slices inherit these assignments.
