# T111 Conditional readable-rule prototype (engine study)

- **Kind**: conditional research prototype; planning brief under [programme #433](https://github.com/diegoami/goal2-archaeology/issues/433).
- **Issue**: [#450](https://github.com/diegoami/goal2-archaeology/issues/450); **Branch**: `task/T111-engine-study`; **Merge after**: T110.
- **Difficulty**: hard; **Size**: M (2–4 active hours; re-estimate after T110; compute separate); **Complexity**: high; **Impact**: medium.
- **Rating rationale**: Compatibility and fair comparisons are complex. The prototype informs a decision rather than delivering a playable engine.
- **Implementer**: main session or the session's selected implementer, using repository tools. **Reviewer**: independent strong-model review for new rule claims; milestone review in T113.
- **Evidence**: T110 option assessment and an explicitly recorded owner choice; selected original/port routines and their controls.
- **Owns**: `docs/engine-study/prototype.md`, `notes/engine-study/T111/` (isolated prototype and immutable comparisons). The executable slice fixes exact source/annotation ownership before dispatch.
- **Scope**: After the owner selects a design, build the smallest isolated non-production prototype that tests whether named structures and rules can preserve the chosen compatibility contract. A bounded skill/contest slice is a candidate, not a preselected architecture. Keep the existing implementation as the reference.
- **Acceptance outcomes**: Document the explicit design approval, selected slice and observables before coding. Differential tests cover ordinary and boundary inputs plus a failing control; report readability evidence, behaviour, timing and known limits. A narrow result never claims whole-engine equivalence.
- **Dispatch gate / Done when**: this brief records scope and expected research results, not executable readiness. Split into independently mergeable, approximately one-hour slices before dispatch; each gets its own issue, ownership and contract. Validate each slice's Done-when commands as failing on pre-task main and passing on a mock fix. Require source/evidence checks, relevant controls and `python3 tools/check_links.py`; ordinary research outcomes above remain mandatory. Also require an explicitly recorded owner design decision after T110 before coding.
- **Hazards**: This backlog entry authorises planning only. Implementation is blocked on T110 and an explicit design decision, plus any execution/proof prerequisite the assessment identifies.

Use the [programme's methods, rating definitions and gates](../engine-study-plan.md).
New measurements have immutable source-pinned receipts; a budget is set before a heavy job.
This package does not select a production backend or silently repair original behaviour.
