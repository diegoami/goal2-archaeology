- **Scope**:
  - `runtime/driver/`: a library and CLI: `launch(config, start_state)`, `keys(...)`,
    `screen()` (text, 80×25, with sha256), `memory(addr, n)` from a savestate, `save_state()`,
    `restore(state)`, `terminate()`. Every wait is a bounded poll or a delay written into the record.
    May copy from `runtime/spike/`; the spike stays unchanged.
  - `runtime/driver/cycle.py`: restore a start state → keys → screen read → reset, writing one
    `run/1` record per cycle in `runs/E002/`. Each record carries: the host UTC time and the host
    local time with its timezone (DOS time follows local time) at launch and at each read, the DOSBox-X config (with sha256), the cycles setting, the BIOS tick count and video
    mode as I1 memory reads, and the start state's sha256.
  - `findings/F003-*.md` (`proposed`): G-M1's exit check, with its runs.
  - Not in scope: controlling the clock or the RNG (I3); registering `runtime_writes`
    (game-archaeologist#19); any game rule.
- **Done when**:
  1. `python3 runtime/driver/cycle.py --runs 10 --start-state title` writes 10 records in
     `runs/E002/`; `python3 tools/validate_runs.py runs/E002` passes; the 10 `before` screen hashes
     are identical, and so are the 10 `start_state.sha256`.
  2. At least 10 of the records restore a savestate (`start_state.restore` names Host+L), and in
     each one the screen digest after the restore equals the digest stored with the savestate.
  3. Every record of a completed cycle has an I1 observation of a memory read: the mode byte at
     `0040:0049` (= 03) and the tick count at `0040:006C`, along with the host UTC time and local time
     with timezone. A record of an aborted cycle keeps every read the cycle made, shown by a test.
  4. `python3 -m unittest discover -s tests -v` passes in CI without DOSBox-X. The savestate parser is
     tested on a synthetic savestate built by the test (no original files), and that test fails when
     the text-page offset or the memory offset in the parser changes by one byte (say how you checked).
  5. `grep -n 'sleep' runtime/driver/*.py`: every hit is inside a poll loop or a key hold whose
     duration goes into the record; the output is pasted with one line per hit saying which.
  6. `git diff origin/main --stat -- runtime/spike runs/E001 artifacts` prints nothing.
  7. `git ls-files | grep -vxF tests/fixtures/evidence/local/c82cd5ca5a74f844-after.sav | grep -iE '\.(exe|dat|hlp|hil|pif|bat|com|ovl|sav|gl|sum)$'`
     prints nothing, and no tracked file is larger than 1 MB.
- **Hazards**:
  - losing measurements (game-archaeologist L207): records and logs are committed and pushed after
    each batch and at least every 30 minutes, and are never deleted or overwritten;
  - a shared machine: isle-wars runs DOSBox-X and Xvfb here too. Never use display `:99`, and kill
    only process groups this driver started (by PID, never `pkill`);
  - committing a savestate, a capture or a game file (they stay in `scratch/` and `.cache/`);
  - restoring a savestate into a session that mounted a different folder (F001, Anomalies);
  - reading the clock difference as a rule: record it; the interpretation belongs to G5's Q001.
