## How it was reached: unchanged original keys

The path is goal2's T170e ([goal2#694](https://github.com/diegoami/goal2/issues/694)), rebuilt from nothing but the
owner's date-call savestate (`e039-r0005-date-call.sav`, `0d9c6830…`, already on the owner's Drive) and `GOAL.DAT`:

1. `Core.boot(date-call, (1990,10,4), dos_time=(10,0,20,95), title_key="n")`, then `Driver.new_game(7, "bob")`:
   four keys, 0.22 s, the stage-2 cursor-1 Denmark 1992 manager menu.
2. Six rounds by the season oracle's own play (`play_round(watch=True)`, the original's timers pass every prompt,
   [reach-r1](../../notes/400-roles34/reach-r1/)). Round 6 and round 7 each begin with the original refusing the managed
   eleven ("Denmark has an ineligible player in the first team"); each is answered through the squad screen's own
   keys (swap 125↔135 in round 6, 124↔125 in round 7), no guest-memory edit. **Round 6's menu is kept once**
   and every later attempt starts from `menu-r07-repair1.g2core` (`9ffdcd81…`), not from the boot.
3. Round 7 plays to minute 33 and stops. The unchanged Core stops at `0791:CC54` with
   `UnknownScreen`: its catalogue has role 3 nowhere ([stop-r1](../../notes/400-roles34/stop-r1/), 137 s from the menu).

The Core, pinned: goal2 commit `42c25412a81a397cb40ed28ba54bca7c688d8b07` (T170e merged), copied by `git archive`
(tree hash in every record), CPython with Unicorn 2.1.4. The raw attempts (`notes/400-roles34/<attempt>/`: pinned
`collector.py`, `source.json` written before the run, `steps.jsonl`, `record.json`) were committed before this text
interpreted them. The **only host adaptation** is `adapt()` in the collector for `search-r1` and later: it widens the
Core's screen *label* for CC7B roles 3 and 4 to the label it already gives roles 2 and 5 (same frame checks), so the
Core's own poll service waits at the original's poll and serves the original's own keys. It writes nothing to guest
memory or registers and moves no CPU (the verifier and the test refuse the tokens that would; T90's `uc-r1` made the same
kind of label adaptation for roles 2/5, and `frames.py` reads the real role bytes, never the label).
The branch of Space/Return/Return runs on a *copy* loaded from step 1, so the main run continues exactly as the oracle's.

Two cross-checks of "unchanged": **`reach-r1` and `stop-r1`, which install no adapter, stop at byte-identical
memory and registers**, and that machine is the same machine as step 1 (`verify.py` compares them). And a consumer
check ([consumer-check-r1.log](../../notes/400-roles34/consumer-check-r1.log)): the pinned unchanged Core cannot
`Core.load` steps 1–3 (`UnknownScreen`); with only the label widened it loads each as `set-piece-select` /
`set-piece-pitch`, view role 3, side 1, country 7, slot 11, stored 131.

Replaying the casualties honestly: `reach-r1`'s last observation row failed on a keyword clash in the collector
(`observe_state(..., site=...)`); its raw `017-unknown-screen-r07.ucstate` was already kept and the error is
retained unchanged. `stop-r1` repeats it from the kept menu with the clash fixed. Its zip differs only in entry
timestamps; `verify.py` compares the memory and registers inside.

## What a consumer does

Import step 1 as a genuine Unicorn machine input at its saved CPU. goal2's catalogue (`screens.py`) needs the
CC7B `_taker` label for roles 3 and 4 (a goal2 slice that consumes this evidence; none is made here): the live
selector is then `set-piece-select` (poll `CC54`/`CEDE`, read `CEED`), Space gives `set-piece-pitch`
(`CF3A`), Return returns to the selector and Return accepts. Do not move the CPU to CC7B, CEE8 or CF35.
Side and country come from the loaded state: Denmark is **side 1** here.
