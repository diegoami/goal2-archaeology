## The inputs (private) and how to verify them

The owner's private folder is `goal2drive:goal2-archaeology/400-roles34-20261109/`.
[delivery.json](../../notes/400-roles34/delivery.json) gives every exact filename, full SHA-256, size, private path,
readback path, live-frame fields, the caller `6D4E` frame and the raw record row each came from.

```sh
mkdir -p .cache/400-roles34/core-source
git -C <a goal2 clone> archive 42c25412a81a397cb40ed28ba54bca7c688d8b07 goal2 | tar -x -C .cache/400-roles34/core-source
rclone copy goal2drive:goal2-archaeology/400-roles34-20261109 .cache/400-roles34/readback
unzip -n .cache/400-roles34/readback/t131-all-attempts-private.zip -d .
python3 notes/400-roles34/verify.py
python3 -B -m unittest tests.test_taker_checkpoints_t131 -v
```

The package holds every raw state of every attempt (the menus, the repairs, the branches), the pinned Core source and
the run logs (the Core source also comes from the command above). The verifier executes no guest and imports no goal2
code: it re-derives every frame from the kept bytes, checks each attempt's collector against its recorded Git commit,
recomputes what was met from the raw rows, and hashes the delivered files and the package.

## How they were reached: unchanged original keys

Role 3 is goal2's T170e path ([goal2#694](https://github.com/diegoami/goal2/issues/694)), rebuilt from the owner's date-call
savestate (`e039-r0005-date-call.sav`, `0d9c6830…`, already on the owner's Drive) and `GOAL.DAT`:

   four keys, 0.22 s, the stage-2 cursor-1 Denmark 1992 manager menu.
2. Six rounds by the season oracle's own play (`play_round(watch=True)`, the original's timers pass every prompt,
   [reach-r1](../../notes/400-roles34/reach-r1/), 28 minutes). Rounds 6 and 7 each begin with the original refusing the managed
   eleven ("Denmark has an ineligible player in the first team"); each is answered through the squad screen's own keys
   (swap 125↔135 in round 6, 124↔125 in round 7), no guest-memory edit. **Round 6's and 7's menus are kept once**; every later
   attempt starts from `menu-r07-repair1.g2core` (`9ffdcd81fc3c8119a8cbe0d4c532656c1cb6fa73c82f0ad3670d3a3d903773e5`).

   ([stop-r1](../../notes/400-roles34/stop-r1/), 137 s from the kept menu).

Role 4 came from the same boot with another country's new game, `Driver.new_game(country, "bob")`, rounds from the
menu (no refusal of an eleven in either career): England (9) in 19 minutes to round 3
([search-c9](../../notes/400-roles34/search-c9/)), Albania (1) in 20 minutes ([search-c1](../../notes/400-roles34/search-c1/)).

The Core, pinned: goal2 commit `42c25412a81a397cb40ed28ba54bca7c688d8b07` (T170e merged), copied by `git archive`
(its tree hash is in every record), CPython 3.14 with Unicorn 2.1.4. The raw attempts (`notes/400-roles34/<attempt>/`: the pinned
`collector.py` and `frames.py`, `source.json` written before the run, `steps.jsonl`, `record.json`) were committed
before this text interpreted them. The **only host adaptation** is `adapt()` in the collector, for the search and preceding
attempts: it widens the Core's screen *label* for CC7B roles 3 and 4 to the label the Core already gives roles 2 and 5 (the
same frame checks), so the Core's own poll service waits at the original's poll and serves the original's own keys. It
writes nothing to guest memory or registers and moves no CPU (the verifier and the test refuse the tokens that would; T90's
`uc-r1` made the same kind of label adaptation for roles 2 and 5, and `frames.py` reads the real role bytes, never the label).
Space/Return/Return run on a **copy** loaded from step 1, so the main run continues exactly as the season oracle's.

Cross-checks that it is the unchanged machine: **`reach-r1` and `stop-r1`, which install no adapter, stop at byte-identical memory
and registers, and that machine is step 1** of role 3; **`stop-c9` (England), also with no adapter, stops at step 1 of England's
role 4** (`verify.py` compares memory, registers and load). Albania's unchanged Core stops earlier, at a role 3 of its own, so the
same comparison cannot be made for Albania's role 4 (its input is the adapter run's; the Albania role 3 stop is kept as

case (`UnknownScreen`); with only the label widened it loads each as `set-piece-select` / `set-piece-pitch`, the view naming
the role, side, country, slot and stored pick above.

## What a consumer does

Import step 1 as a genuine Unicorn machine input at its saved CPU. goal2's catalogue (`screens.py`) needs the CC7B `_taker` label
for roles 3 and 4 (a goal2 slice that consumes this evidence; none is made here): the live selector is then `set-piece-select`
(poll `CC54`/`CEDE`, read `CEED`), Space gives `set-piece-pitch` (`CF3A`), Return returns to the selector and Return accepts. Do not
move the CPU to CC7B, CEE8 or CF35. Side and country come from the loaded state: Denmark is **side 1** here, England **side 0**,
Albania **side 1**. The goal2 season comparison needs role 3 only to pass round 7.
