## Method

Read the named view first (seg_0791_02.c: leaders and squad swaps; seg_0791_03.c: starting posts and position groups;
seg_0791_04.c: destinations, depth and marking), then the raw decompiled view and the listings in
seg_0791_03.asm, seg_0791_04.asm, seg_0791_07.asm and seg_0791_08.asm. Whole-match runs corroborate the translation;
they do not supply guessed movement rules. Tables stay in guest memory and are read, not replaced with tuned constants.

## Translation constraints from the static reading

- The sixteen routine entries and exact return conventions come from the listing/backlog row, not Ghidra's inferred
  signatures. 2218, 4532, 4649 and 47C5 read their caller's frame through a passed BP. Their local-stack writes matter.
- 1F3C uses a signed -1 best-score sentinel and a strict unsigned leadership comparison. It calls the leadership reader
  again when replacing a winner. The all-unavailable case reads the pre-existing local winner word; no invented fallback.
- 20E3 can reach the real captain prompt CC7B. Preserve that guest call and the kit's existing answer path. The leadership
  bonus query stays inside the eleven-record loop; hoisting it would change the call counts/registers.
- 2218 makes the listing's three 214B:007B calls for squad words, form bytes and marking words. A local bulk swap would
  erase those observable guest-call boundaries.
- 4B64's code-segment set test (23E4:08DF) branches on its returned zero flag; Ghidra's apparent pointer comparison is
  an inference artifact. The assembly's set bytes and jump decide that branch.
- Use the original guest RNG calls (214B:06B1/06FA and 0791:261A), preserve their order and each caller's registers,
  and read the depth/post tables at their listed DS offsets. Signed byte arithmetic and 16-bit address wrapping stay exact.

## Stack-byte correction before acceptance

The first whole-match batch matched scores, ticks, draws, board, events and result digests, but strict comparison found
DS block `E800` different on reached matches. One reference/port replay of F40/e032-0101 captured the exact final bytes:
DS:EB28–EB2A were `CD 1C 5B` in the reference and `28 3E CD` in the first port. The bytes are in the guest stack
(SS:3E18–3E1A). The watched last writes (`out/T63/stack-diag-trace.txt`) were the unported 1771:3A06 player-skill
reader: the reference entered it with SP:3E18; the first port entered it with SP:3E1A. Its caller was 0791:278A,
called by the ported 47C5 at 4967. The listing pushes the previous AX at 494D, then pops DX at 496A. The first
translation kept that word only in Python and left the guest SP two bytes high for the intervening call. It also
omitted the same push/pop around 47C5's 4980/499D and 49B2/49C0 guest calls and 1FDD's 20A3/20B0 calls. The port
now writes those transient words at the listing sites and restores SP and DX at the listed pop. The ten synthetic
tests pass; removing the 494D push from an in-memory mutant makes the new test fail with an SP and stack-word assertion
(`out/T63/stack-mutation-test.txt`). The paused first-batch JSONL outputs remain as failed candidate evidence;
fresh outputs will be taken after this fix.
