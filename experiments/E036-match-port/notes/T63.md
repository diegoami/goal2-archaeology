# T63: positioning, marking and leaders

Issue #274; route C, P2b. The listing decides the Python translation; Ghidra supplies the initial control-flow map.

## Method

Read the named view first (seg_0791_02.c: leaders and squad swaps; seg_0791_03.c: starting posts and position groups;
seg_0791_04.c: destinations, depth and marking), then the raw decompiled view and the listings in
seg_0791_03.asm, seg_0791_04.asm, seg_0791_07.asm and seg_0791_08.asm. Whole-match runs corroborate the translation;
they do not supply guessed movement rules. Tables stay in guest memory and are read, not replaced with tuned constants.

## Translation constraints from the static reading

- The sixteen routine entries and exact return conventions come from the listing/backlog row, not Ghidra's inferred
  signatures. 2218, 4532, 4649 and 47C5 read their caller's frame through a passed BP. Their local-stack writes matter.
- 1F3C uses a signed -1 best-score sentinel and a strict unsigned leadership comparison. It calls the leadership reader
  again when replacing a winner. The all-unavailable case reads the pre-existing local winner word; no invented fallback.
- 20E3 can reach the real captain prompt CC7B. Preserve that guest call and the kit's existing answer path. The leadership
  bonus query stays inside the eleven-record loop; hoisting it would change the call counts/registers.
- 2218 makes the listing's three 214B:007B calls for squad words, form bytes and marking words. A local bulk swap would
  erase those observable guest-call boundaries.
- 4B64's code-segment set test (23E4:08DF) branches on its returned zero flag; Ghidra's apparent pointer comparison is
  an inference artifact. The assembly's set bytes and jump decide that branch.
- Use the original guest RNG calls (214B:06B1/06FA and 0791:261A), preserve their order and argument words,
  and read the depth/post tables at their listed DS offsets. Signed byte arithmetic and 16-bit address wrapping stay exact.
  The port does not claim all scratch-register effects of the listing: AH on some skip/clear returns, DX/CX after
  arithmetic, and stale AX at several guest-call entries are unverified as observable. The current callers read AL,
  and the affected callees do not read AX on entry; strict ordinary runs still check observable consequences.

The first acceptance records above were made before the R1 correction. They remain immutable evidence for that
source; their equality alone did not prove the port owned the continuation after 1FDD's A920 call. The listing at
2074 pushes `element`, A920 at A9B5 pops only its `winner` argument, and the held `element` becomes the first
argument of 278A at 20A0. The port now keeps that word on the guest stack across A920 and hands it to 278A.
The synthetic guest-call driver applies the callee's return pop and checks SP at each return. Its test enters
1FDD through 20E3, reaches both 278A continuation sites, proceeds through all marking slots and both sides,
and reaches all 22 leadership bonus calls. The original two-argument A920 call failed the new return-SP check.

The second 47C5 loop increments BP-3 at 49D3 on each no-match path, leaving 12 before the 48B0 exit test.
Its early match returns before that increment. The test checks both the no-match terminal value and an early
match value. A listing sweep of the other local loops found their existing terminal values correct: 47C5's first
loop reaches 12; 1F3C and 1FDD end at 11; 20E3's side and inner marking/bonus loops end at 1, 5 and 11;
419C ends at side 1 and the last slot. No other local-loop translation changed.

The R1–R4 mutation controls operate on isolated copies of the runtime and tests. Deleting the held A920 word,
the 49D3 increment or the 4A1B clear, and forcing group-4 attack/defend limits to 0/255, each produces an
assertion failure without an import error. The controls and exact test source are in `out/T63/rework-mutations.py`.
The R5 suggestions (4B64 table addresses, the 0D1C upper bound, the 4C97 write and 2218's middle destination)
