# T73: display boundary and independent access proof

Issue #284. This page records the boundary claims and their evidence. An initial
all-at-once removal is deliberately not an accepted boundary: it changed the
match. Later preserved-state candidates and the independent original watches
separate that failure from permitted screen differences.

## Owner decision

The owner chose **strict display profile; preserve legacy behavior** on
2026-10-23. New display-profile comparisons use only independently proved DS
byte ranges and compare every DS digest block over that mask. They exclude only
the board's screen digest and the duplicate full_time.data.screen_sha256 path
from the new producer's event digest. Every other event field/count and every
other compared field remain protected. Ordinary unprofiled --no-screen keeps
its historical behavior and tests; it is not used for T73 acceptance.

The narrowly scoped family.py change is a mechanical blocker outside the task's
original Owns: selecting the declared display profile by default for display/all
ports and producing the same screen-only event projection for the new original
reference and candidate. It does not change the record schema or runtime kit API.

## Static-first method

All 88 named routines were read first, then the relevant instruction listings
and direct callers/return forms were inventoried in out/T73/static-inventory.json.
That inventory names every listing location, caller, callee and return cleanup.
The draft classification below is constrained by those reads and independent
original accesses, never by masking bytes because a candidate differed.

The 685-block unhooked ALL run is exact 62/62; 412 blocks and 66 routine entries
are reached. The older 44-entry estimate in the task was a narrower inventory.
The snapshot/engine picture and every copy of it stay protected. A841 copies
all 4000 bytes of its rendered setup buffer into the engine background: even a
text writer is not blindly disposable when its output feeds that copy.

## Original-only watch controls

The initial whole-DS MEM_READ observer perturbed this Unicorn backend's live
return stack, even when the observer was a no-op. The original stopped early at
E7DD:8DB0. Removing all register reads, and adding a global no-op CODE observer,
did not cure it. MEM_READ_AFTER is exposed as a constant but registration is
rejected with UC_ERR_ARG. These failed probes and their records are retained;
they are not mask evidence. MEM_WRITE alone, entry observers alone and kit
io_tap alone are exact controls against the same T57 match.

The nonperturbing watch excludes DS[AD10,ED10), the live stack window between
SS's DS-relative base (match.py SS_PARAGRAPH) and the actual initial A96E/A972
text-buffer boundary. Every unobserved byte is explicitly **unmaskable**; stack
differences are never suppressed. The observed ranges are DS[0,AD10) and
DS[ED10,10000). This limits potential masks rather than weakening comparison.

The observer caches the physical instruction address in CODE callbacks. Memory
callbacks do not query VM registers. The fast mode records the actual static
instruction/routine owner; shared helpers outside T73 remain ineligible and are
not called pure display merely because a display caller invoked them. Semantic
kit reads are separate from only the explicit memory-digest/footprint snapshots
and screen hashing. Kit semantic stats, bars, result/seed reads are protected.

O8/c1-c2-friendly fast profile: exact against T57, 366.80s wall, 399.57s CPU,
41347 unique attributed access keys, 32364689 reads and 1861333 writes. Resource
sample after report assembly was 139648KiB RSS before JSON serialization. Full
optional-caller-context profile was also exact, 1550.82s, 145652KiB at that point.
Future compressed watch outputs include a separate post-serialization full-peak
RSS/time/source-hash receipt. Closed original JSON profiles are retained as-is.

## Duplicated screen event field

out/T73/event-fields-a/summary.json compares actual original/candidate event
field digests, without recording event text. Both have 1211 events; the only
differing field is event 1209 full_time.screen_sha256. Removing exactly that
field makes the complete streams equal. The ordinary event digest remains raw.
The new isolated producer projection and its tests retain seed, statistics,
kind, minute, score, decisions, nested screen-named fields and event count.

## Unit checks

The owned tests exercise preserved glyph/occupancy/picture writes, text-cell
loops/attributes/direction, string temporaries/coordinates, score rows, the
snapshot's 51 memory copies and 42 string copies, No-replay flag clearing and
the semantic board/key site. Profile tests require DS-only masks (explicitly selected empty profiles are valid),
refuse missing/mismatched profiles and references, and prove strict profile mode
cannot inherit the legacy block 59 exemption. The existing 45 comparison tests
pass unchanged (unit-legacy-compare-1.txt). No profile mask is accepted before
its original ALL watch proof and semantic protection audit.

## Explicit profile selection, including an empty mask

Profile mode is selected separately from byte-mask contents. Display/all CLI
metadata requires the declared profile, including when its mask is empty.
The unhooked display reference is produced with the existing --mask option
pointing to the declared families/display/mask.json path; that context selects
the screen-event projection even for []. An ordinary raw run or another empty
mask file remains unprofiled. The mode is carried to workers and checkpoint
identity without adding a record field or runtime kit API. Missing, wrong
masks/profiles or a reference outside the bound profile path fail closed in
new display mode. Legacy unprofiled behavior remains unchanged.

## Concrete unmaskable difference diagnostic

out/T73/memory-diff-a runs both actual matches unmasked and emits only changed
addresses/counts/digests, never original bytes. With the preserved core,
text-to-pitch and snapshot writes, records, w5c8a0, w5eb30 and the entire pitch
background have zero different bytes. DS still has 3514 different bytes: the
performance-string length at 0E86, line backup AA04..AAA3, attribute AAB2,
stack ranges within E600..EB28 and text buffers from ED10 upward. This
candidate is not accepted. Those differences are not mask evidence: the stack
is unobserved and ineligible; the original-only access sample shows outside-row
writers/readers of the text buffers. Preserving more of those writes/frame
residue or seeking explicit scope guidance is required before the boundary
can satisfy the strict acceptance contract. No blanket mask is introduced.

## Owner scope decision and complete original proof

After the concrete unmaskable differences were shown, the owner chose
**preserve byte-exactness; port needed memory effects** on 2026-10-23.
Necessary renderer, ABI and local-memory effects within the 88 routines remain
in scope. This is not a user-facing UI/backend, and it introduces neither a
contract revision nor an unproved stack mask. The implementation must preserve
those bytes rather than relabel them display-only.

The complete independent watch has 62/62 raw original records identical to
T57, all 88 entry counters per match equal the separate unhooked coverage run
(5456 checks, zero mismatches), and one observer source hash. Peak reported
RSS was 217196KiB; the longest case 1753.61s. The source hash is
5b6e10b70f5a5390f99ed500d728e8e85a868bf6afb09a0ea25a10b882899635.
The root's sealed-batch audit is at commit 0d7d22c.

out/T73/access-candidates-all-complete-1.json was generated with
analyze_watch.py --require-all, validates every original record against T57,
and finds 69 access-only candidate bytes in 11 ranges. These are factual
write/read constraints, not automatic approval to mask state-bearing bytes.
A separate static/semantic justification remains required for each selected
range. No candidate port run is an input to that analysis.

The fixed 255de405 baseline and 29 one-line state/profile mutations are all
caught by the 22 owned tests (out/T73/test-controls-1.txt). The controls read
baseline runtime/dependencies without a worktree, overlay only the T73 files
for a mutation, and require a behavioral assertion failure.
