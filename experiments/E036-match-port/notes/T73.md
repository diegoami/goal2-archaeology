# T73: display boundary and independent access proof

Issue #284. This page records the boundary claims and their evidence. An initial
all-at-once removal is deliberately not an accepted boundary: it changed the
match. Later preserved-state candidates and the independent original watches
separate that failure from permitted screen differences.

## Owner decision

The owner chose **strict display profile; preserve legacy behavior** on
2026-10-23. New display-profile comparisons use only independently proved DS
byte ranges and compare every DS digest block over that mask. They exclude only
the board's screen digest and the duplicate full_time.data.screen_sha256 path
from the new producer's event digest. Every other event field/count and every
other compared field remain protected. Ordinary unprofiled --no-screen keeps
its historical behavior and tests; it is not used for T73 acceptance.

The narrowly scoped family.py change is a mechanical blocker outside the task's
original Owns: selecting the declared display profile by default for display/all
ports and producing the same screen-only event projection for the new original
reference and candidate. It does not change the record schema or runtime kit API.

## Static-first method

All 88 named routines were read first, then the relevant instruction listings
and direct callers/return forms were inventoried in out/T73/static-inventory.json.
That inventory names every listing location, caller, callee and return cleanup.
The draft classification below is constrained by those reads and independent
original accesses, never by masking bytes because a candidate differed.

The 685-block unhooked ALL run is exact 62/62; 412 blocks and 66 routine entries
are reached. The older 44-entry estimate in the task was a narrower inventory.
The snapshot/engine picture and every copy of it stay protected. A841 copies
all 4000 bytes of its rendered setup buffer into the engine background: even a
text writer is not blindly disposable when its output feeds that copy.

## Original-only watch controls

The initial whole-DS MEM_READ observer perturbed this Unicorn backend's live
return stack, even when the observer was a no-op. The original stopped early at
E7DD:8DB0. Removing all register reads, and adding a global no-op CODE observer,
did not cure it. MEM_READ_AFTER is exposed as a constant but registration is
rejected with UC_ERR_ARG. These failed probes and their records are retained;
they are not mask evidence. MEM_WRITE alone, entry observers alone and kit
io_tap alone are exact controls against the same T57 match.

The nonperturbing watch excludes DS[AD10,ED10), the live stack window between
SS's DS-relative base (match.py SS_PARAGRAPH) and the actual initial A96E/A972
text-buffer boundary. Every unobserved byte is explicitly **unmaskable**; stack
differences are never suppressed. The observed ranges are DS[0,AD10) and
DS[ED10,10000). This limits potential masks rather than weakening comparison.

The observer caches the physical instruction address in CODE callbacks. Memory
callbacks do not query VM registers. The fast mode records the actual static
instruction/routine owner; shared helpers outside T73 remain ineligible and are
not called pure display merely because a display caller invoked them. Semantic
kit reads are separate from only the explicit memory-digest/footprint snapshots
and screen hashing. Kit semantic stats, bars, result/seed reads are protected.

O8/c1-c2-friendly fast profile: exact against T57, 366.80s wall, 399.57s CPU,
41347 unique attributed access keys, 32364689 reads and 1861333 writes. Resource
sample after report assembly was 139648KiB RSS before JSON serialization. Full
optional-caller-context profile was also exact, 1550.82s, 145652KiB at that point.
Future compressed watch outputs include a separate post-serialization full-peak
RSS/time/source-hash receipt. Closed original JSON profiles are retained as-is.
