## The choice for a decision under a port, and why

A decision the kit stops for inside a guest call (the notice 7FCF that 6E11's call of 8062 reaches) is answered where it
stands, by the original's own stop, with no nested emulation and no thread:

- A port that calls the original is a Python generator. `yield call(...)` pushes the arguments and the listing's return
  address (the instruction after the listing's call, inside the routine the port replaces, so the stack's bytes are
  the original's), points CS:IP at the callee and returns from the Unicorn hook. The guest then runs the callee in the
  same `emu_start` as any guest code: the kit's hooks fire, its writes and draws reach the kit, a ported callee runs
  as its port. When the guest reaches the return address with SS:SP back where the call left it, the machine's
  dispatch (after the kit's handlers there, as for a port at an entry) resumes the generator with the callee's AX.
- A stop inside the callee is an ordinary stop: `emu_start` returns, the match yields its decision, the policy answers,
  the run resumes at the stopped instruction (the hook replayed), and the port goes on only when the callee returns.
  The hazard of the brief (a nested run that the kit stops returning into Python as if the call had ended) cannot
  arise: there is no nested run, and a frame resumes only at its own return address with its own SP (tested).
- Why not a nested `emu_start` with the match in its own thread: it needs every run of the match in a worker thread
  and a hand-off at every stop, exceptions carried across threads, and a timeout for the nested run; the generator
  needs none, and the stack holds the original's bytes. The price: a port with guest calls is written with `yield`
  (a helper that calls the guest is `yield from`), and while a frame waits the match cannot be saved (its Python
  frame is not in the guest's memory): `save()` refuses with `MatchError` naming the frame.
- Unicorn 2.1.4 applies a code hook added during a run only to code it has not yet translated (probed in the
  scratchpad: a hook added at an address of a block already translated never fired; `ctl_remove_cache` on the address
  made it fire). A guest call's return address is hooked the first time it is used, so `Machine.at_linear` drops the
  address's translation (`test_a_return_address_in_code_already_translated_is_reached`).

## The proof mode and the locator

`Match(ports=..., prove=N)` proves every call of a ported routine from the N-th draw on (port/prove.py), E021's rule
(the written bytes in order outside the routine's dead frame, and the returned registers, equal) in this order:

1. The port runs first, live: it is the match. Its writes are recorded with the bytes they replaced (the guest's,
   the port's, and the kit's own through `Machine.write`), and so is every kit site it reaches: the address, CS:IP and
   SS:SP there, and, in the order the handlers made them, what they read (memory bytes, registers with EFLAGS and the
   segments, stack words: `Machine.io_tap`), the registers they set and the bytes they wrote; the kit's reads made
   between two runs while the match stands stopped at the site (a decision's answer) belong to it (a site that
   stopped the match and was replayed on resume is one visit). The prover's own reads bypass the taps.
2. At the port's return it is undone and the CPU put back to the entry; the original runs muted (no handler, port or
   write listener of the kit runs in it; another ported routine it calls runs as the original's). At each kit site it
   reaches, the port's run's visit is replayed in the kit's place: same address, same order, same CS:IP and SS:SP (a
   site a port fired from Python: the address). Its events are taken in order: each read is compared with the
   original's byte or register first (round 2: else ProofError names the site, the byte or register, the port's run's
   value and the original's), each set and write applied. So the kit answers the original as it answered the port,
   only where the original gave it the same inputs, and a decision is asked once.
3. At the original's return: the sites (none missing, none left over), the bytes, each site's place among the written
   bytes (the same count before it in both runs) and the registers are compared; ProofError names the first
   difference. Then the original is undone and the port's writes and registers put back.

Every armed call is proved or raises ProofError. A call made inside a proved call (a ported routine the port calls)
runs as its port; its writes and sites are compared as part of the call that holds it, and (round 3) its returned
registers at its own return, against the original's call of the same rank to return (`nested`); a call before the
armed draw is `before`. The kit's write listeners (round 3) are proved like sites: each call in the port's run is
kept with the write it was given and its events (reads, `pc()` included), and paired at the original's same write
(muted, they do not run there) with its reads compared and its answer applied. A port that answers a key read itself
(mem.read_key, mem.keypressed) is refused under a proof (PortError): its key would have no replay. So are a write of
the kit's outside its handlers and listeners, and (round 3) a stop made by a write listener or by a site a port
fires.

**AX and DX are always compared**, but for a (routine, return address) declared in `prove.RESULT_DEAD` with the static
evidence that the caller never reads them there; a difference there is counted as `dead`. One entry: the pilot's
8889 returning to 8BB7 (its only call, 8BB4 in 8AE9). AX: 8BC1/8BC5 write AL and 8BC7 AH before 8BCC reads AX. DX:
`out/T59/liveness.py`, a liveness search over the listing (each half of AX/DX followed along every path, into callees
and back through every listed caller, anything it cannot model counted as a read), finds DX written before it is
read on every path from 8BB7, through 8AE9's callees and back to 8AE9's two callers 7881 and 9564
(`liveness-8BB7-b.txt`; no data reference to 8AE9 in datarefs.tsv). Its controls (`liveness-controls.txt`): a read in
the routine, a read by the caller after the return, and a write first, each as expected. T58's port of 8889 leaves
AX and DX as its own code does, not as the original's last 86D0 call; it is not this task's to change.

Round 1 of the review (sol-6.1) found the first design's two holes, both closed here: AX and DX were exempted for
any port returning None (R1), and a call whose original reached a kit site was undone and run unproved (R2).

The proof's hooks are added once, when the Match is made (a write hook over all memory: a proved match costs about 160 s
against 22 s). `locate.py` reads the reference and the candidate, finds the first differing per-minute draw row,
re-runs the match with the candidate's ports proved from that row's first draw (from the start when nothing differs
there), and names the first call that differs. It writes only `--out`, a new file.

## Round 4 (sol-6.1 round 3, R1: the order of the kit's observed events; code 170b5c2)

The finding: listener calls were paired against their own sequence and sites against theirs, and a site's place was
checked only among the live written bytes, so a listener call on a write in the otherwise dead frame (G's saved BP)
moved across a site was proved. The class: any event the kit observes whose order relative to the others was not
compared. The kit observes a proved call only through its sites (the handlers at an address, or a site a port fires),
its write listeners (on_write, watch), and, inside the call, the entries and returns of nested ported routines (their
returned registers are compared); its reads and register changes happen inside a site or a listener call (and between
runs at a stopped site), so they belong to those events. A guest call is not observed by the kit as such: its pushes
are writes (bytes, and listener calls if a listener covers them) and its callee's sites and listeners are events.

The fix (prove.py): the port's run keeps ONE ordered transcript of those events (site, listener call, nested entry,
nested return); the original's run checks each of its events against the transcript's next as it comes (`_expect`),
and the first out of order is named at the return, after the written bytes, the listener pairing and the sites'
places (so a byte that differs is still named as such), with an event left over named too. The per-kind checks stay.

## Round 6 (sol-6.1 round 5: R1 an MMIO callback, R2 a raw register read; deny by default; code 45d5800)

The findings: round 5's guard forwarded everything but `hook_add`/`hook_del`, so `Machine.uc.mmio_map` installed host
callbacks that ran in both runs and in the rollback (R1), and a kit site reading `Machine.uc.reg_read` saw the port's
BX without the input check (R2). The cause was the design (forward everything but a list).

The design now (machine.py `_HookGuard`, `UC_WHITELIST`):
- **Under a proof** (from the first line of `Prover.__init__` that passes its refusals, so during construction too)
  `Machine.uc` forwards only `UC_WHITELIST`: the engine's register-range constants and `ctl_get_arch`, `ctl_get_mode`,
  `ctl_get_page_size`, `ctl_get_cpu_model` (queries of the engine's configuration: no callback, no guest state). Any
  other attribute, a future Unicorn API included, raises PortError naming it. Nothing is cached on the guard and it
  cannot be assigned to, so the check is made at every access.
- **Before a proof** everything is forwarded and every use is counted (`foreign_hooks`); the proof refuses to start on
  a machine whose `Machine.uc` was used at all. That covers the callbacks installed before construction (`hook_add`,
  `mmio_map`, `mem_map_ptr`, a remap: `UC_FOREIGN` lists those that install a callback or share or change guest
  memory) and a bound method kept for later (a raw `reg_read` taken before the proof and called during it, which no
  check at call time would see). Unproved runs keep their uses (`family.py --count`).
- **The tapped route**: the kit reads and writes the guest only through Machine's methods (`read`, `word_at`, `rd`,
  `rd_far`, `reg`, `set_reg`, `pc`, `write`, `wr`), which the proof records and compares (rounds 2-3).
- **Internal route**: the machine, the proof and the port's view (port/mem.py, its reads) use the engine itself,

### The limit, accepted by the owner (2026-10-18; follow-up issue #333)

What the proof guarantees: it catches accidental divergence by ports and by kit handlers written in the ordinary
way. Every observation or callback route that goes through Machine's public API (its methods, `Machine.uc`, the taps,
the sites and the write listeners) is compared or refused.

What it does not: deliberate reflection. In-process Python cannot be sandboxed against its own code: private
attributes (`Machine._uc`, `Machine.uc._engine`), `vars()`, `object.__getattribute__`, the `__self__` of a
whitelisted bound method, `gc`, `ctypes`, frame inspection. Sol's round-6 review (medium) found four such routes, and
the owner accepted them as known on 2026-10-18 and merged 8235db9 with the limit documented (no further code round):
- R1: the private engine references `m._uc`, `m.uc._engine`, `vars(m.uc)["_engine"]` and
  `object.__getattribute__(m.uc, "_engine")` bypass the denial and the pre-proof use count (a raw `hook_add` made
  through `m.uc._engine` before the `Prover` is built is accepted);
- R2: a whitelisted bound method discloses the engine (`m.uc.ctl_get_arch.__self__ is m._uc`), so a kit handler could
  `reg_read` through it unchecked.

A port or a kit handler must never use any of these routes; they are the machine's, the proof's and the port view's
internal route only.
