# T58: the port mode in the kit, with E032's pilot moved in

Issue #269. Tooling, no game rule: the kit (`runtime/original_match/`) runs Python ports in place of the original's
routines, and E032's pilot (`0791:8889` with `86D0` and their helpers) is the first module, `port/pilot.py`.

## What was built

- `machine.py`: `Machine.port(address, runner)` (a port at a routine's entry runs after every kit hook there, only when
  none stopped); `Machine.on_write` (one list of write listeners for guest writes, through Unicorn's hook, and for a
  port's writes); `Machine.write_as(linear, size, value, at)` (a port's write reaches every listener as the
  instruction `at` would, `pc()` reading `at` meanwhile); `Machine.fire(address)` (the kit's hooks at a site inside a
  ported routine); `no_replay_at` (a stop made inside a port resumes at its return as a fresh start). `watch` is
  built on `on_write`, so a port's write reaches the event watches and the draw record (`record_draws`, moved from a
  direct Unicorn hook to `on_write`).
- `port/mem.py`: the memory view (`Mem`; `MachineMem` over the machine, `PlainMem` over plain memory for tests and
  T78): reads, writes naming the original's instruction, `arg(i)`, `frame(bp)`, `enter(n, at)`, `site()`,
  `read_key()`, `keypressed()`; a decision reached inside a port is refused (`PortError`).
- `port/__init__.py`: per-module registries (`Registry`: ports, variants, stubs), `load(specs)`, `install()`, the
  runner (entry, the port, AX/DX, `ret n`/`retf n` as the listing writes it).
- `port/pilot.py`: E032's pilot against the view, every write naming its instruction (seg_0791_14.asm 86F0, 8711,
  8725, 8739, 874E, 89E1, 8A26, 8A5B, 8A79, 8AA5, 8AC1, 8ADD; the seed's 214B:069F); its three falsifiers as variants.
- `match.py`: `Match(..., ports=...)`, the key services for ports (`_PortKeys`: 08DD's writes 08EA, 0947, 097C),
  `result()["ports"]`, a save naming its ports (`opts["ports"]`, the calls in `st["port_calls"]`), `VERSION` 3 (loads 2).
- `check.py`: `--ports`, `--variant`; in the port mode a stopped match or step FAILs and the run goes on, and the
  family step prints each seed and the ports' calls.

## What a port cannot do yet

- Stop for a decision: a port is Python and cannot be suspended mid-routine; a decision reached inside one is a
  `PortError`. A stop for queued events (the tick) takes effect at the port's return.
- Call a routine that is still the original's (T59).
- Leave the dead stack bytes the original's prologue and calls write below SP (a port's frame lives in Python unless
  it uses `mem.enter`): no step compares them.
