## What the port had to be, and why

- **Registers.** The proof (port/prove.py) compares AX and DX at every return, so each port returns what the listing leaves in
  both: `mul` leaves the high word in DX, `xor ah, ah` makes AH 0, a `mov al` keeps AH, `cdq; idiv` leaves the remainder in DX,
  and the routines that return through another routine's register state (3179 carries 3041's AH and DX through the 08DF tests;
  5A03 carries its caller's AH and DX) are written that way. The caller's registers at entry are read where the listing
  never overwrites them (5A03, 3E2F).
- **The dead stack.** The families' memory digests cover the 64 KiB of DS, and the game's stack segment (SS 3875 over DS 2DA4)
  lies inside it, DS:AD10..ED10. A first run with ports that kept their frames in Python (no stack writes) was identical in
  every field but two 1 KiB blocks of DS (57 and 58, the stack's deepest part) in the S/ko-42-quick-g19 match; nothing else
  differed. So each port writes the bytes the original leaves on the stack: its frame (`mem.enter`, the pointer locals, the
  result locals, the loop variables), and the pushes, the far return and the frame of every helper it calls. `T58`'s note says
  no step compares those bytes; the digests do, as this run found. `3216` (about 340,000 calls a match) tests the three
  elements inline and writes its 20 bytes of stack as one block (`put`: the view's own write, no watch of the kit covers the
  stack); every other helper is a guest call, so its pushes, frame and registers are the original's.
- **Guest calls.** The helpers `214B:0C57`, `0C79`, `0CA1`, `0018`, `09DA` and `23E4:075A`, `06B7`, `06E3`, `0644`, `08DF` stay
  the original's (T60 ports them; when it merges they run as its ports). The Turbo Pascal string helpers leave the destination
  pointer on the stack (`retf 2`, `retf 4`), which `call()` cannot say: the port pushes the pointer words itself (`push`) and, for
  the next call that consumes them, takes them back (`drop`) and gives them as that call's arguments (same words, same
  addresses). `08DF` answers in the zero flag: the port reads EFLAGS after the call (`set_test`). A routine of this module a port
  calls (3179 calls 3088 and 3041, 377E calls 3216 and 3179, 3EF8 calls 3E2F and 3216, ...) is a guest call too, so every call
  is counted and proved on its own, and the first nested ports on real matches (T59 left it to synthetic tests) work: the proof
  compares them inside their caller and at their own return.
- **3E2F** is a nested procedure: its first argument is 3EF8's BP and it reads and writes 3EF8's frame (the two position
  strings at BP-0x10 and BP-0x1B, the marks at BP-0x27). 3EF8 therefore keeps those in the real frame (`mem.enter(0x32)`), not in
  Python.
- **377E** is written from the listing; T43's model (`runtime/model/quick_engine.py`) is not called. The unit test runs the
  port on all 162 literal answers `tests/test_model_condition.py` holds for the original's 377E.
- **Sets in the code segment** (CS:3139 = 88 04, CS:3159 = 10 09, CS:3411 = 1B 00; the strings CS:0E6A, CS:2E91) are read by the
  original's 08DF and 06B7 from the code segment; the port passes their addresses and holds no byte of them. The simulator in
  the tests writes the three 2-byte rows and the two strings from the listing's data rows.

## The tests and their mutations

`mutations-second.txt`: 42 mutations of attributes.py, one at a time, each makes `SimTests` or `VariantTests` fail (no emulator
needed); `mutations-frames-fca0a83.txt`: 5 more, of frames and registers, caught only with the differential tests. The first
mutation run found eight the tests did not catch (a boundary at age 0x15, the empty slots of 34E7, the fourth row of 3E2F's table,
the unavailable opponent and the team tactic of 3EF8, DX after 377E's halving, and the dead frame, which the simulator does not
model); tests were added for each, and one mutation (377E's energy read unsigned) is equivalent (a negative energy is
unavailable first) and was removed. `mutations-fca0a83-first.txt` is that first run, kept.

## Not verified, and things to know

- The full suite's result is in `full-suite-*.txt`; see the PR body for the failures it has on this machine and on `main`.
- A port's speed: ALL with the ports costs about 40 s a match against 8-17 s unhooked (the framework's per-call cost: 340,000
  calls of 3216 a match; `3216` itself is one read of the record, one of the stack block and one write).
- `08DF`'s zero flag is read from EFLAGS after the guest call. When T60 ports `08DF` its port must set ZF as the original does for the
  unported callers anyway; if it does not, 3179, 3431 and 5A03 will differ in the families (and the proof will name the routine).
- The simulator's models of the helpers are written from the listing and are not exact in everything (the registers other than the
  ones a test reads); the differential tests use the original's.
- Unicorn 2.1.4; the machine is shared, other tasks' runs queued for the two heavy slots, so wall times vary.
