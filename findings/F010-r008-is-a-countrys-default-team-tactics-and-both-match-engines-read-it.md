- The words are at `DS:6AC0` … `DS:6BB0` (`static:static/goal-exe/strings.tsv`). - **Player +0xF holds per-player overrides of elements 1..4** (static, about 90%). Element i + 4 of +0xF says the player has his own setting for tactic i (i = 1..4), and element i of +0xF is that setting. Otherwise the team's +0x2D element i applies. Three readers apply this rule: the match's `0791:26D7` (`static:static/goal-exe/decompiled/seg_0791_02.c:313` – `static:static/goal-exe/decompiled/seg_0791_02.c:324`), `1771:0BC4` (`seg_1771_02.asm:218`–`242`) and the player screen `1771:3BD3` (F008; the ` P` suffix). - **What `1771:3431` derives: overrides from the player's own fields, not from +0x2D** (static, about 90%; F007 traced the same writes). `3431` reads no byte of the country record (`static:static/goal-exe/code/seg_1771_05.asm:405` – `static:static/goal-exe/code/seg_1771_05.asm:482`). That is an override of tackling to "avoid injury". Then the position byte +6 decides; the two branches exclude each other:
    - **Positions {0, 1, 3, 4}** (goalkeeper, sweeper, left and right back; set byte 0x1B at `1771:3411`, `je` = not a member, `:429`–`433`): it sets element 5, then element 1, and returns (`3471`–`3495`, `:434`–`448`). That is an override of position to "push forward", or "leave box" for a goalkeeper. (static:static/goal-exe/code/seg_1771_05.asm:402)
    - **Any other position**: `349A` compares +6 with 2, and `349F` returns for every position but 2 (`:450`–`455`). Only a centre back (position 2) goes on: (static:static/goal-exe/code/seg_1771_05.asm:451)
      - when +5 < 14 (`34A4`, `jae` past it), it sets element 5; (static:static/goal-exe/code/seg_1771_05.asm:454)
      - then, in all cases, it sets element 6, then element 2 (`34AB`–`34DC`, `:456`–`477`). (static:static/goal-exe/code/seg_1771_05.asm:456)
      So a centre back always gets the override of possession to "quick pass". A centre back with +5 < 14 also gets an override of position whose value is element 1 as it stands, which is "stay back" once +0xF has been cleared, because `3431` never sets element 1 for position 2. ## Inferences

- **When `0791:BC5D` runs, and whether a managed team's tactics survive it** (static; about 70% for survival, below). `BC5D(c)` runs in this order (`static:static/goal-exe/code/seg_0791_19.asm:465` – `static:static/goal-exe/code/seg_0791_19.asm:528`):
    1. It clears +0xF for each of c's 20 squad words, zero or not (`BC7E`–`BCA3`). (static:static/goal-exe/code/seg_0791_19.asm:480)
    2. It calls `BBFF(R008[c], c)` (`BCB0`), so c's tactics go back to the default and the overrides are re-derived. (static:static/goal-exe/code/seg_0791_19.asm:498)
    3. It calls `52CC(c)` (`BCB6`), whose "unavailable sorts last" rule applies when `0B77(c)` is nonzero at that moment. (static:static/goal-exe/code/seg_0791_19.asm:500)
    4. It sets +6 of slots 1..11 from R011 (`DS:9F02 + 20 c + slot`; `BCC2`–`BCFB`). (static:static/goal-exe/code/seg_0791_19.asm:504)
  Its callers, each with the guards on the path to the call:
  - `000E:01FA(m)` (`static:static/goal-exe/code/seg_000E_01.asm:210` – `static:static/goal-exe/code/seg_000E_01.asm:363`). Before any test, it writes 1 to two bytes of manager m's records (`0229`, `0231`) and calls `BC5D` for m's country (`023F`, line 236). Only afterwards does it:
    - copy +7 to +6 for slots 12..20 (`024B`–`0298`); (static:static/goal-exe/code/seg_000E_01.asm:240)
    - clear byte 0 of m's 80 extra players (`02BC`–`02E2`); (static:static/goal-exe/code/seg_000E_01.asm:281)
    - write the country's own number to +0x2E (`02FD`, line 306), after which `0B77` (+0x2E > 0x80) no longer reports it managed; (static:static/goal-exe/code/seg_000E_01.asm:306)
    - turn the country's fixtures with first byte 0xFE into 0xFF (`0375`–`037E`). (static:static/goal-exe/code/seg_000E_01.asm:353)
    So this reset runs while the country is still managed: `52CC` in step 3 sorts with the managed rule. That `01FA` is a manager leaving is inferred.
  - `000E:6970` (`static:static/goal-exe/code/seg_000E_08.asm:931` – `static:static/goal-exe/code/seg_000E_08.asm:1160`): `0791:D47E`, `B7FA`, `B602` and `D050`, in that order, then `BC5D` for both teams, with no test of `0B77` (`69C5`–`6A36`). `D47E` calls `A3DE`, `0BC4` and `B19D`: a result without display.
  - `0791:E80D` (`static:static/goal-exe/decompiled/seg_0791_09.c:590` – `static:static/goal-exe/decompiled/seg_0791_09.c:638`; listing `E80D`–`E926`). First it calls the match set-up `A4A1` (`E818`). Then it shows the template `DS:3A36` (its text `Do you want to watch this match ?` is at `DS:3A7D`) and loops until Y, N or Esc.   **How `000E:6CA7` routes a fixture** (`seg_000E_09.asm:54`–`446`):
  - **First byte 0xFE** (`6D79`): the flag is 1 when `0B77` is zero for both teams and 0 otherwise (`6D86`–`6DA3`). `6C21(flag)` returns 1 without calling `E80D` when the flag is 0, and otherwise returns what `E80D` returns (`static:static/goal-exe/code/seg_000E_09.asm:6` – `static:static/goal-exe/code/seg_000E_09.asm:49`). When it returns 1, the fixture goes to `6E15`. There, `BB2F` is called when the fixture's byte +2 is 0 and `F1F6` otherwise (`6EDB`–`6F18`).
  - **Any other first byte, or a 0 from `6C21`**, goes to `6DAE`. Two tests on the fixture's byte +2 can each call `6C21(1)`, and so `E80D`, and go to `6E15` when it returns 1: membership in set `0x695A` (`6DBB`–`6DCB`), and membership in set `0x697A` together with a nonzero continent flag (`6DE7`–`6E10`). Otherwise the fixture goes to `6970` (`7013`–`7014`). (static:static/goal-exe/code/seg_000E_09.asm:166)
  A fixture with a managed team and first byte 0xFE therefore never reaches `E80D` or `6970`; it goes to `BB2F` or `F1F6`, which leave the managed team's +0x2D alone. A fixture with a managed team and another first byte could reach either, and both reset both teams. The code shows that `E80D` writes 0xFE to a computer-only fixture that is not watched, and that `01FA` turns a released country's 0xFE fixtures into 0xFF. Whether a managed team's fixtures always carry 0xFE was not established. So "a managed team's edited tactics persist from match to match until `01FA`" rests on that, about 70%. The runs bear on one match only. The edit changed three quick results, which it could not have done had +0x2D been put back to R008 before `D733` and `0BC4` read it.

## Method

- **Static first** (CLAUDE.md rule 22). Every claim above was first read in the decompiled view. Each rule it states, meaning each condition, guard and order of calls and stores, was then traced in the listing from the routine's entry to the statement, and the listing addresses are given with the rule. The decompiled view's argument order and branch directions were not relied on (review rounds 1 and 2 found two misreadings of it). The places where the view hits F009's trust limits are the membership tests `23E4:08DF` in `3431` (`seg_1771_05.asm:429`–`433`, `je` = not a member) and `0BC4` (`seg_1771_02.asm:206`–`210`, `jne` = member), and the 0x2D accesses of `D733` (`seg_0791_21.asm:867`, `:897`). The string and data tables are from `static/goal-exe/strings.tsv` and `static/goal-exe/data/`. `experiments/E008-q005-r008-tactics/readers.py` lists every routine whose listing accesses `es:[di + 0x2d]` (or `add di, 0x2d`) and loads `[0xa917]`, or accesses `+0xf` and loads `[0xa91b]`, and computes reachability from `0791:9564` and `0791:D733` over `calls.tsv`'s direct edges. That is a filter, so each listed routine was read, and two false positives are named above. An access through a pointer the routine did not load itself would escape it. No such reader turned up in the decompiled view's grep for `0x2d` (`static/goal-exe/decompiled/*.c`).
- **Why runs were made**: static analysis answered every claim. The runs corroborate one of them, "the quick result reads the managed team's +0x2D", as rule 19 needs for `corroborated` and as the task's scope asks. No run was made for a missing tool.
- **Runs** (`experiments/E008-q005-r008-tactics/run.py`, README and amendment 1): E006's published main-screen states (release E006, sha256 in each record), restored in a fresh DOSBox-X 2024.03.01 process (`cycles=30000`, as E004 and E006). Then E004's keys `Esc Up Enter Enter` to the captain screen, and a savestate there. The arm's state is loaded with Host+L: the same savestate (`unchanged`), or a copy with the one byte edited (`edited`; `runtime/driver/savestate.py` `with_memory`; I3, declared in the record). The byte is read back, then E004's quick result (`Enter r`, `runtime/driver/match.py`) runs to full time. Records are under `runs/E008/`, `python3 tools/validate_runs.py runs/E008` passes, and `summarise.py` part 3 prints the table.
- **Continental table**: `summarise.py` part 1 computes +0x2A..+0x2C from `GOAL.DAT` (`.cache/goal2/GOAL.DAT`, verified against set `goal2-67cf27d6`; the block offsets from `static/goal-dat/blocks.tsv`). It compares the rating with the mean of field +3 of each continent's squad players in E006-r0001 (F007: all 12 E006 games are identical). No new run was made for it.

## Limits

- The watched-match claims are static only. No watched match was run with an edited byte.
- What each statistics counter (`DS:7B7E`, `DS:7B82`, `DS:7B83`) is, and the screen labels of elements 5..7, were not read.
- How large the shift of `0BC4` is next to the line sums (`0AA7` reads the manager table `[DS:A91F]`), and what each element does in a watched contest, are Q010–Q012.
- One managed country (Denmark) and one byte value (0xBA) were tested. The fixtures are each start state's next match.
