## Answer

- **+0x2D is a Pascal set of eight team tactics, element k at bit k − 1** (static). The set helpers are `214B:0C57` (test), `0C79` (include) and `0CA1` (exclude), each on bit `k − 1` (`seg_214B_01.c:913`–`934`). The tactics screen prints all eight elements in the order `DS:6BC0` = 5, 6, 7, 1, 2, 3, 4, 8, each as the word `DS:6AA0 + 32 k + 16 · bit` (`seg_1771_01.c:1112`–`1119`, data `ds_2581_03.hex` row 6BC0). F008's tactics panel prints elements 1..4 and 8 the same way. About 95% for the bits and words; the screen labels of elements 5..7 are not read here.

| Element (bit, mask) | Clear | Set | Readers in a match (below) |
| --- | --- | --- | --- |
| 1 (bit 0, 0x01) "position" | stay back | push forward | quick: `0791:D733`, `1771:0BC4`; watched: `0791:26D7` from `42CB`, `4532`, `4A28`, `4E28` |
| 2 (bit 1, 0x02) "possession" | keep ball | quick pass | watched: `26D7` from `5049` |
| 3 (bit 2, 0x04) "passing" | short passes | long passes | watched: `26D7` from `3111` |
| 4 (bit 3, 0x08) "tackling" | avoid injury | go in hard | quick: `0791:D5C1`; watched: `26D7` from `4DA9` |
| 5 (bit 4, 0x10) | half pitch | full pitch | quick: `D733`, `0BC4`; watched: `26D7` from `4649`, `4A28`, `4B64` |
| 6 (bit 5, 0x20) | sag back to box | stand ground | quick: `0BC4`; watched: `26D7` from `4649`, `4B64`, `5729` |
| 7 (bit 6, 0x40) | play safe | offside trap | watched: `26D7` from `4532`, `4B64` |
| 8 (bit 7, 0x80) "mark" | zonal | man to man | both: `1771:3EF8` (man-marking pairs), reached through `0791:230C` |

  The words are at `DS:6AC0` … `DS:6BB0` (`static/goal-exe/strings.tsv`). For a goalkeeper the player screen swaps element 1's and 3's words for `stay in box`/`leave box` and `throw the ball`/`kick from hand` (`DS:0EA6`, `DS:0EC6`; `1771:3BD3`, `seg_1771_03.c:31`–`35`; F008). Denmark's R008 is 0x8B: push forward, quick pass, go in hard, man to man (`GOAL.DAT` 0xA078; E008-r0001's read of +0x2D).
- **Player +0xF holds per-player overrides of elements 1..4** (static, about 90%). Element i + 4 of +0xF says the player has his own setting for tactic i (i = 1..4), and element i of +0xF is that setting. Otherwise the team's +0x2D element i applies. Three readers apply this rule: the match's `0791:26D7` (`seg_0791_02.c:313`–`324`), `1771:0BC4` (`seg_1771_02.asm:218`–`242`) and the player screen `1771:3BD3` (F008; the ` P` suffix). Elements 5..8 have no override: `26D7` reads them from +0x2D alone, because it tests `param_2 < 5` first.
- **What `1771:3431` derives: overrides from the player's own fields, not from +0x2D** (static, about 90%; F007 traced the same writes). `3431` reads no byte of the country record (`seg_1771_05.asm:405`–`482`). When `2FFB` (= +5 − (+3 and 1)) < 4, `33CD` sets element 8 of +0xF and clears element 4. That is an override of tackling to "avoid injury" (`:384`–`397`). For positions {0, 1, 3, 4} (goalkeeper, sweeper, left and right back; set byte 0x1B at `1771:3411`), it sets elements 5 and 1, an override of position to "push forward" (or "leave box" for a goalkeeper; `:429`–`448`, `3465`–`3495`). For position 2 (centre back) it sets elements 6 and 2, an override of possession to "quick pass". It also sets element 5 when +5 < 14, an override of position to "stay back" (`:450`–`477`, `3497`–`34DC`). `3431` only sets bits (and `33CD` clears element 4), so the callers that want a fresh derivation clear +0xF first: `0791:BC5D` (`seg_0791_08.c:17`–`22`), `1771:34E7` (`seg_1771_02.c:948`–`966`) and `0791:C5DC` (`seg_0791_08.c:512`–`514`). `0791:BBFF` does not clear it (`seg_0791_07.c:1351`–`1358`).
- **What `1771:52CC` does: the squad order, not the tactics** (static, about 85%). It sorts the country's squad words in slots 1..11 and 12..20 (`DS:0F3A`/`DS:0F3C` = 1, 11 and 12, 20; `ds_2581_01.hex` row 0F20) by position byte +6, through `1771:517A`. For a managed country, players `1771:3216` reports unavailable sort as position 0x0E (last). Each slot then gets its old position byte back (`seg_1771_03.c:921`–`968`). It reads neither +0x2D nor +0xF.
- **The quick result reads +0x2D three ways** (both routes for "reads"; static for "how"). Static, about 90%:
  - `0791:D733` tests elements 5 and 1 of each team's +0x2D once per call (`seg_0791_21.asm:867`, `:897`; `seg_0791_08.c:1165`–`1186`). With chance 1/`DS:0A90[bit]` (1/11 clear, 1/10 set) it adds 1 to the team's statistics byte `DS:7B7E + 10 t`. With chance 1/`DS:0A8E[bit]` (1/60 clear, 1/30 set) it adds 1 to `DS:7B82 + 10 t` and to the other team's `DS:7B83`. These are counters of the statistics screen `0791:0106` (`seg_0791_01.c:100`–`110`); which statistic each is was not read.
  - `D733` calls `1771:0BC4` for both teams (`seg_0791_08.c:1160`–`1161`). `0BC4` sums each line's strength into `DS:9B45 + 2 t + 4 k`, for k = keeper, defence, midfield, attack (the tactics screen's right column prints `keeper`, `defence`, `midfield`, `attack`, `DS:4D0A`…`4D78`). For each outfield player of the first 11 and each of elements 1, 5 and 6 (set constant 0x62 at `1771:0BA4`, tested at `seg_1771_02.asm:206`–`210`, a member when `jne` is taken), it adds `1771:0AA7(country) div 8` to the attack sum when the player's effective setting is set (`:259`) and to the defence sum when it is clear. So with push forward, full pitch and stand ground, a team moves strength from defence to attack.
  - `D733`'s goals come from `0791:B19D` (`seg_0791_07.c:889`–`925`). For each attempt there are three contests: rand(the opponent's midfield) < rand(own midfield), then rand(2 · the opponent's defence) < rand(own attack), then rand(the opponent's keeper) < rand(own attack). All three won is a goal.
  - `D733` calls `0791:D5C1` when no goal fell in the call (`seg_0791_08.c:1271`–`1273`). It lets a tackle event go ahead when the tackler's effective element 4 is set (go in hard), and otherwise only with chance 1/20 (`:1113`–`1116`).

  **Behavioural**: from four start states, the quick result with Denmark's +0x2D XOR 0x31 (elements 1, 5, 6 flipped, 0x8B → 0xBA) differs from the unchanged arm in three. The full-time score bytes and seed word `DS:7B62` (the word at the far pointer `DS:A978`, `2DA4:7B62` in all ten records) read:

| Start state | unchanged | edited | unchanged again |
| --- | --- | --- | --- |
| `e006-1000-r0001` | 1 0, 0x63d7 (r0001) | 0 1, 0xf6a9 (r0002) | 1 0, 0x63d7 (r0003) |
| `e006-1337-r0004` | 0 1, 0x5109 (r0004) | 0 1, 0x5109 (r0005) | 0 1, 0x5109 (r0006) |
| `e006-2100-r0005` | 0 0, 0xf970 (r0007) | 0 1, 0x543a (r0008) | — |
| `e006-0630-r0008` | 1 3, 0x7dfd (r0009) | 1 0, 0x5aeb (r0010) | — |

  The unchanged arm repeats exactly in both states where it was run twice, as F006 found for any one state. So the differences come from the one edited byte. That byte reads back as 0xBA after the load in all four edited runs. One state in four is unchanged by the edit. Static analysis allows this: the edit changes the bounds of `B19D`'s draws, not how many draws `D733` makes. I put "the quick result depends on the managed team's +0x2D" at about 95% (both routes). How much each tactic shifts the odds is Q010–Q012.
- **The watched match reads +0x2D through each player's effective setting** (static, about 85%). `0791:26D7(player, k)` returns the player's effective element k (`seg_0791_02.c:304`–`324`). The watched engine `0791:9564` reaches it through its event routines: `3111` (k = 3), `42CB` (1), `4532` (7, 1), `4649` (6, 5), `4A28` (5, 1), `4B64` (6, 5, 7), `4DA9` (4), `4E28` (1), `5049` (2), `5729` (6). For example 9564 → `8AE9` → `57AC` → `474D` → `4532` (direct call edges, `static/goal-exe/calls.tsv`). The quick result reaches the same routines only through a tackle's play-out (`D733` → `D5C1` → `7EEF` → … → `8AE9`). Element 8 drives `1771:3EF8`: with man to man, each player without the "protect zone" flag (+0x10 element 7) is paired with an opponent to mark in `DS:9A3E + 0x28 t + 2 slot`. With zonal the pair is 0 (`seg_1771_03.c:224`–`238`). `0791:230C` calls it, which both engines reach. `0BC4`'s line sums are not reached from `9564` except through the team menu (`9372` → `ED8A` → `1771:1981` → `157D`). The watched engine is not run here, so this claim is static only.
- **Every reader and writer of +0x2D, and of player +0xF** (static; `readers.py` lists the routines by listing access, filtered on a load of the array pointer; `summarise.py` part 2 prints them with direct-call reachability; the routines below were each read in the decompiled view. Through screens and menus almost everything is reachable from both engines, so "in a match" below means reached without the team menu `ED8A`):
  - `1771:9A40` writes R008 to +0x2D at a new game (`seg_1771_06.c:110`–`112`). Not in a match.
  - `0791:BBFF(value, c)` writes +0x2D and calls `3431` on the 20 players (`seg_0791_07.c:1340`–`1361`). Callers: `BC5D` and the computer's in-match tactic changes `BD83`, `BF6B`, `C01A`, `C0DF`.
  - `0791:BD83` (match set-up `A3DE`, and `C173`) puts a computer team back to R008. If the opponent's first 11 are stronger (`BD03`, sums of `1771:377E`), it includes rand(6) twice. For team 1 with `DS:80FC` it includes element 1 (`seg_0791_08.c:63`–`99`). `0791:C173`, after a goal (`65FE`, both engines), does this for each computer team. At a one-goal difference it calls `BD83`. At two goals `BF6B` includes (when behind) or excludes (when ahead) rand(6) three times. At more, `C01A` (behind) includes rand(5) five times and element 6, or `C0DF` (ahead) excludes them, once per match (`DS:8332`, `DS:8334`; `seg_0791_08.c:248`–`297`, `:142`–`245`). A managed team is never changed: `C173` and `A3DE` skip it (`1771:0B77`).
  - `0791:D733`, `1771:0BC4`, `0791:D5C1`, `0791:26D7`, `1771:3EF8`: the readers above.
  - `1771:3BD3`, `3B3F`: the player screen (F008). `1771:157D`/`1981`: the tactics screen, which shows +0x2D and edits it by toggling elements (`214B:0CF4`, `seg_1771_01.c:1196`). It is reached from the main menu (`000E:7439`) and from the match's team menu `0791:ED8A`, which sets `DS:9B55` when +0x2D changed (`seg_0791_09.c:929`–`935`). Not in a match except through that menu.
  - `1771:4B61`: the player's own tactics, which toggles +0xF elements i and i + 4 (`seg_1771_03.c:630`–`650`). Reached from `0791:E44F` and the main menu only.
  - Writers of +0xF: `1771:3431`, `33CD` (above). `0791:BC5D`, `1771:34E7` (match set-up `A3DE`, computer teams) and `0791:C5DC` (a computer player leaving the pitch) clear it and re-derive it. The +0xF hits in `0791:86D0` and `8AE9` are byte +0xF of another record, the on-pitch object at `[param + 6]` (`seg_0791_06.c:270`–`416`), not the player's.
- **When `0791:BC5D` runs, and whether a managed team's tactics survive it** (static, about 80%). `BC5D(c)` clears +0xF of c's 20 players and calls `BBFF(R008[c], c)`, so c's tactics go back to the default and the overrides are re-derived. It then calls `52CC(c)` and sets +6 of slots 1..11 from R011 (`DS:9F02 + 20 c + slot`) (`seg_0791_08.c:6`–`32`). Its callers:
  - `000E:01FA`, when a manager leaves a country: +0x2E goes back to the country's own number (`seg_000E_01.c:82`–`137`);
  - `000E:6970`, after a match the round loop `000E:6CA7` lets the computer play out (`0791:D47E`), for both teams (`seg_000E_05.c:38`–`40`);
  - `0791:E80D`, the "watch this match?" prompt for a match between two computer teams (reached from `000E:6C21` only when neither team is managed), for both teams (`seg_0791_09.c:634`–`638`);
  - `0791:BB2F` and `0791:F1F6`, after a match with a managed team, only for the team that `1771:0B77` says is not managed. The managed team gets `0791:BA4E` instead, which touches neither byte (`seg_0791_07.c:1295`–`1338`, `:1255`–`1293`; `seg_0791_09.c:1094`–`1112`).

  The match set-up `0791:A3DE` re-derives +0xF and adjusts +0x2D for computer teams only (`seg_0791_07.c:235`–`266`). So a managed team's edited +0x2D and +0xF persist from match to match until its manager leaves it (`01FA`). The 80% covers the flag-driven branches of `6CA7` (`23E4:08DF` membership tests). Those branches decide which path a fixture takes, and they are read in the decompiled view only. The four edited runs agree for one match: the edited byte was not reset before the quick result.
- **Continental means of the rating fall in the help file's order; single countries do not** (both routes). From `GOAL.DAT` blocks 8 and 9 alone (`summarise.py` part 1; `1771:9A40` sets +0x2B, +0x2C, +0x2A as F007 says, `seg_1771_06.c:85`–`99`), the rating `1771:10E7` over the 32 countries of each continent is:

| Continent (+0x2C) | Mean | Min | Max | E006 measured mean of +3 − 0x7F (E006-r0001) |
| --- | --- | --- | --- | --- |
| 1 Europe | 82.656 | 30 | 126 | 82.656 |
| 2 America | 53.062 | 6 | 111 | 53.062 |
| 3 Africa | 41.906 | 4 | 92 | 41.906 |
| 4 Asia | 32.812 | 1 | 67 | 32.812 |

  The means fall in the order of `GOAL.HLP` 171–173 ("European teams are on the whole better then American teams, which in turn are better than African teams, with Asian teams being the most lowly"). The help file says "on the whole", and the ranges overlap: Europe's weakest country (30) rates below the best of every other continent, Asia's best is 67. The rating gives each continent step 0.5 · (33 − rank) per country, plus half the world-rank term. The measured +3 (rating + 0x7F, F007) gives the same four means to three decimals. The help file numbers the continents 1 Europe, 2 America, 3 Africa, 4 Asia (`GOAL.HLP` 163–166), and `DS:690A` holds EUROPEAN, AMERICAN, AFRICAN, ASIAN in that order. I put the order at about 95%, and the naming of +0x2C as the continent at F007's 85%.

## Method

- **Static first** (CLAUDE.md rule 22). Every claim above was first read in the decompiled view, then in the listing where the view hits F009's trust limits. Those places are the membership tests `23E4:08DF` in `3431` (`seg_1771_05.asm:429`–`433`, `je` = not a member) and `0BC4` (`seg_1771_02.asm:206`–`210`, `jne` = member), and the 0x2D accesses of `D733` (`seg_0791_21.asm:867`, `:897`). The string and data tables are from `static/goal-exe/strings.tsv` and `static/goal-exe/data/`. `experiments/E008-q005-r008-tactics/readers.py` lists every routine whose listing accesses `es:[di + 0x2d]` (or `add di, 0x2d`) and loads `[0xa917]`, or accesses `+0xf` and loads `[0xa91b]`, and computes reachability from `0791:9564` and `0791:D733` over `calls.tsv`'s direct edges. That is a filter, so each listed routine was read, and two false positives are named above. An access through a pointer the routine did not load itself would escape it. No such reader turned up in the decompiled view's grep for `0x2d` (`static/goal-exe/decompiled/*.c`).
- **Why runs were made**: static analysis answered every claim. The runs corroborate one of them, "the quick result reads the managed team's +0x2D", as rule 19 needs for `corroborated` and as the task's scope asks. No run was made for a missing tool.
- **Runs** (`experiments/E008-q005-r008-tactics/run.py`, README and amendment 1): E006's published main-screen states (release E006, sha256 in each record), restored in a fresh DOSBox-X 2024.03.01 process (`cycles=30000`, as E004 and E006). Then E004's keys `Esc Up Enter Enter` to the captain screen, and a savestate there. The arm's state is loaded with Host+L: the same savestate (`unchanged`), or a copy with the one byte edited (`edited`; `runtime/driver/savestate.py` `with_memory`; I3, declared in the record). The byte is read back, then E004's quick result (`Enter r`, `runtime/driver/match.py`) runs to full time. Records are under `runs/E008/`, `python3 tools/validate_runs.py runs/E008` passes, and `summarise.py` part 3 prints the table.
- **Continental table**: `summarise.py` part 1 computes +0x2A..+0x2C from `GOAL.DAT` (`.cache/goal2/GOAL.DAT`, verified against set `goal2-67cf27d6`; the block offsets from `static/goal-dat/blocks.tsv`). It compares the rating with the mean of field +3 of each continent's squad players in E006-r0001 (F007: all 12 E006 games are identical). No new run was made for it.

## Limits

- The watched-match claims are static only. No watched match was run with an edited byte.
- What each statistics counter (`DS:7B7E`, `DS:7B82`, `DS:7B83`) is, and the screen labels of elements 5..7, were not read.
- How large the shift of `0BC4` is next to the line sums (`0AA7` reads the manager table `[DS:A91F]`), and what each element does in a watched contest, are Q010–Q012.
- One managed country (Denmark) and one byte value (0xBA) were tested. The fixtures are each start state's next match.
